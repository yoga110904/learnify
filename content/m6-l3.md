## Masalah: test yang bergantung pada dunia luar

```python
def ambil_cuaca(kota):
    resp = requests.get(f"https://api.cuaca.com/{kota}")
    return resp.json()["suhu"]

def test_ambil_cuaca():
    assert ambil_cuaca("Bandung") == 30     # 😱
```

Test ini bermasalah dari banyak sisi:

- Butuh internet — gagal di CI yang tanpa jaringan.
- Lambat — ratusan milidetik per pemanggilan.
- Hasilnya berubah-ubah — suhu asli tidak selalu 30.
- Bisa kena rate limit atau biaya API.
- Tidak bisa menguji kasus "server error 500".

**Mock** menyelesaikan semuanya: ganti bagian yang lambat/tidak terkendali dengan objek palsu yang berperilaku sesuai skenario.

## `Mock` — objek serba bisa

```python
from unittest.mock import Mock

m = Mock()
m.apa_saja()                 # tidak error, mengembalikan Mock baru
m.return_value = 42
print(m())                   # 42

m.json.return_value = {"suhu": 30}
print(m.json())              # {'suhu': 30}
```

Mock juga **mencatat** bagaimana ia dipakai — inilah yang membuatnya berguna untuk pemeriksaan:

```python
m = Mock()
m("Bandung")

m.assert_called()                    # pernah dipanggil?
m.assert_called_once()               # tepat sekali?
m.assert_called_with("Bandung")      # dengan argumen ini?
print(m.call_count)                  # 1
print(m.call_args)                   # call('Bandung')
```

Mock yang lebih ketat:

```python
from unittest.mock import MagicMock
m = Mock(spec=["get"])       # hanya .get yang boleh diakses
m.post()                     # 💥 AttributeError — menangkap typo
```

## `patch` — menukar sementara

`patch` mengganti sebuah nama selama blok berjalan, lalu mengembalikannya seperti semula.

```python
from unittest.mock import patch

def test_ambil_cuaca():
    with patch("cuaca.requests.get") as fake_get:
        fake_get.return_value.json.return_value = {"suhu": 30}

        assert ambil_cuaca("Bandung") == 30
        fake_get.assert_called_once()
```

Bisa juga sebagai decorator:

```python
@patch("cuaca.requests.get")
def test_ambil_cuaca(fake_get):
    fake_get.return_value.json.return_value = {"suhu": 30}
    assert ambil_cuaca("Bandung") == 30
```

### Aturan emas: patch di tempat ia DIPAKAI

Ini kesalahan nomor satu dalam mocking.

```python
# cuaca.py
from requests import get      # nama "get" sekarang milik modul cuaca
```

```python
patch("requests.get")     # ❌ tidak berpengaruh
patch("cuaca.get")        # ✅ benar
```

Patch bekerja dengan mengganti atribut pada objek modul. Kalau modulmu sudah menyalin referensinya, yang harus diganti adalah salinan itu.

## Menguji jalur gagal

Ini nilai terbesar mocking: menciptakan kondisi yang sulit dibuat secara nyata.

```python
def test_api_mati():
    with patch("cuaca.requests.get", side_effect=TimeoutError):
        assert ambil_cuaca("Bandung") is None     # fallback harus jalan
```

`side_effect` bisa berupa exception, fungsi, atau daftar nilai berurutan:

```python
m = Mock(side_effect=[1, 2, 3])
m(); m(); m()        # mengembalikan 1, lalu 2, lalu 3
```

## Jangan berlebihan

Mock terlalu banyak = test yang hanya menguji mock-mu sendiri, bukan kode sungguhan. Pedoman:

- Mock **batas sistem**: jaringan, database, waktu, filesystem, layanan pihak ketiga.
- Jangan mock logika internal yang sebenarnya cepat dan deterministik.
- Sediakan test integrasi (jumlahnya sedikit) yang benar-benar menyentuh sistem asli.

## Ringkasan

- Mock menggantikan ketergantungan eksternal agar test cepat dan stabil.
- Mock mencatat pemanggilan sehingga bisa diperiksa (`assert_called_with`).
- `patch` menukar nama sementara — patch di lokasi ia dipakai.
- `side_effect` memudahkan menguji skenario error.

## Kesalahan umum

- Mem-patch lokasi definisi, bukan lokasi pemakaian.
- Lupa mengatur `return_value` sehingga hasilnya objek Mock, bukan data.
- Mem-mock semuanya sampai test tidak lagi membuktikan apa pun.
