## Ketika `if` saja mulai berantakan

Kamu sudah bisa `if`/`elif`/`else`. Lesson ini soal pola-pola yang membuat percabangan tetap terbaca saat kasusnya bertambah banyak.

## `match` / `case` (Python 3.10+)

Untuk mencocokkan satu nilai dengan banyak kemungkinan, ada sintaks khusus:

```python
perintah = "hapus"

match perintah:
    case "tambah":
        print("Menambah data")
    case "hapus":
        print("Menghapus data")
    case "keluar":
        print("Sampai jumpa")
    case _:
        print("Perintah tidak dikenal")
```

`case _` adalah penangkap sisa, setara `else`. Tanpa itu, nilai yang tidak cocok cuma dilewati diam-diam.

Beberapa nilai dalam satu cabang pakai `|`:

```python
match hari:
    case "Sabtu" | "Minggu":
        print("Libur")
    case _:
        print("Kerja")
```

Dengan syarat tambahan (*guard*):

```python
match nilai:
    case n if n >= 85:
        print("A")
    case n if n >= 70:
        print("B")
    case _:
        print("C")
```

### Kapan pakai `match`, kapan `if`?

| Situasi | Pilihan |
|---|---|
| Membandingkan satu nilai dengan banyak pilihan tetap | `match` |
| Kondisi kompleks yang melibatkan banyak variabel | `if`/`elif` |
| Pemetaan nilai sederhana (kode → nama) | `dict` |

⚠️ `match` cuma ada di Python 3.10 ke atas. Kalau kodemu harus jalan di versi lama, pakai `if`/`elif` atau dict.

### Mencocokkan struktur data

Kekuatan sesungguhnya `match` adalah membongkar bentuk data:

```python
titik = (0, 5)

match titik:
    case (0, 0):
        print("di titik asal")
    case (0, y):
        print(f"di sumbu Y, y={y}")
    case (x, 0):
        print(f"di sumbu X, x={x}")
    case (x, y):
        print(f"di ({x}, {y})")
```

Ini sering dipakai untuk memproses respons API yang bentuknya bermacam-macam.

## Dict sebagai tabel keputusan

Untuk pemetaan sederhana, dict mengalahkan rantai `elif` dalam keterbacaan **dan** kecepatan:

```python
NILAI_HURUF = {
    "A": 4.0,
    "B": 3.0,
    "C": 2.0,
    "D": 1.0,
}

bobot = NILAI_HURUF.get(huruf, 0.0)
```

Rantai `elif` memeriksa satu per satu dari atas; dict langsung menemukan lewat hash — bedanya terasa kalau pilihannya puluhan.

Dict juga bisa memetakan ke **fungsi**:

```python
def tambah(): return "menambah"
def hapus(): return "menghapus"

AKSI = {"tambah": tambah, "hapus": hapus}

aksi = AKSI.get(perintah)
if aksi:
    print(aksi())
else:
    print("tidak dikenal")
```

Pola ini disebut *dispatch table* dan sangat sering dipakai di kode produksi untuk menghindari rantai `if` raksasa.

## Menggabungkan kondisi dengan `in`

```python
# ❌ bertele-tele
if ext == "jpg" or ext == "png" or ext == "gif" or ext == "webp":

# ✅
if ext in ("jpg", "png", "gif", "webp"):
```

Untuk daftar yang panjang dan sering dicek, pakai `set` — pengecekannya lebih cepat:

```python
GAMBAR = {"jpg", "png", "gif", "webp"}
if ext in GAMBAR:
    ...
```

## `any()` dan `all()`

Untuk mengecek banyak kondisi sekaligus:

```python
nilai = [80, 90, 65]

print(all(n >= 70 for n in nilai))    # False  -> semua harus lulus?
print(any(n >= 85 for n in nilai))    # True   -> ada yang dapat A?
print(any(n < 0 for n in nilai))      # False  -> ada nilai tidak valid?
```

| Fungsi | `True` kalau |
|---|---|
| `all(...)` | semua elemen truthy (list kosong → `True`) |
| `any(...)` | minimal satu elemen truthy (list kosong → `False`) |

Perhatikan perilaku list kosong — `all([])` bernilai `True` ("tidak ada yang melanggar"). Ini logis tapi sering mengejutkan.

Dua fungsi ini juga short-circuit: `any` berhenti di `True` pertama, `all` berhenti di `False` pertama.

## Memvalidasi input bertingkat

Pola yang akan sering kamu tulis:

```python
def validasi_umur(teks):
    if not teks:
        return False, "Umur tidak boleh kosong"
    if not teks.isdigit():
        return False, "Umur harus berupa angka"

    umur = int(teks)
    if umur < 0 or umur > 150:
        return False, "Umur di luar rentang wajar"

    return True, ""

ok, pesan = validasi_umur("abc")
print(ok, pesan)     # False Umur harus berupa angka
```

Perhatikan strukturnya: **satu aturan per blok, keluar lebih awal saat gagal, pesan spesifik untuk tiap kegagalan.** Jauh lebih berguna daripada satu `if` raksasa yang cuma bilang "input tidak valid".

## Ringkasan

- `match`/`case` (Python 3.10+) untuk mencocokkan satu nilai dengan banyak pilihan; `case _` menangkap sisanya.
- Dict lebih rapi dan lebih cepat daripada rantai `elif` untuk pemetaan nilai.
- Dispatch table (dict berisi fungsi) menggantikan rantai `if` raksasa.
- `x in (a, b, c)` menggantikan rantai `or`; pakai `set` untuk daftar panjang.
- `all()` dan `any()` mengecek banyak kondisi sekaligus; perhatikan perilakunya pada list kosong.

## Kesalahan umum

- Memakai `match` di Python di bawah 3.10.
- Lupa `case _` sehingga nilai tak dikenal lewat begitu saja.
- Menulis rantai `elif` puluhan baris untuk hal yang cukup dengan dict.
- Mengira `all([])` bernilai `False`.
