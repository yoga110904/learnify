## Bentuk dasar panggilan API

Hampir semua penyedia LLM memakai format pesan yang sama:

```python
import os
import requests

def tanya(pertanyaan):
    resp = requests.post(
        "https://api.anthropic.com/v1/messages",
        headers={
            "x-api-key": os.environ["ANTHROPIC_API_KEY"],
            "anthropic-version": "2023-06-01",
            "content-type": "application/json",
        },
        json={
            "model": "claude-sonnet-4-5",
            "max_tokens": 1024,
            "messages": [{"role": "user", "content": pertanyaan}],
        },
        timeout=30,
    )
    resp.raise_for_status()
    return resp.json()["content"][0]["text"]
```

Pakai SDK resminya kalau bisa — dia sudah menangani retry, streaming, dan penguraian respons.

Simpan di file `.env` dan masukkan `.env` ke `.gitignore`.

```python
from dotenv import load_dotenv
```

Key yang ter-push ke repo publik biasanya ditemukan bot dalam hitungan menit. Kalau itu terjadi, **cabut key-nya segera** — mengganti commit saja tidak cukup karena riwayatnya tetap ada.

## Percakapan berlanjut

API tidak punya ingatan. Kamu yang menyimpan riwayatnya:

```python
riwayat = []

def chat(pesan_baru):
    riwayat.append({"role": "user", "content": pesan_baru})
    jawab = panggil_api(riwayat)
    riwayat.append({"role": "assistant", "content": jawab})
    return jawab
```

Riwayat akan terus membesar dan biayanya ikut naik. Strategi umum: simpan N pesan terakhir, ringkas yang lama, atau potong berdasarkan jumlah token.

## Streaming

Tanpa streaming, pengguna menatap layar kosong beberapa detik. Dengan streaming, teks muncul bertahap:

```python
with client.messages.stream(...) as aliran:
    for teks in aliran.text_stream:
        print(teks, end="", flush=True)
```

Total waktunya sama, tapi terasa jauh lebih responsif.

## Biaya

Ditagih per token, dan **input biasanya lebih murah dari output**.

```python
def perkiraan_biaya(token_in, token_out, harga_in, harga_out):
    return (token_in / 1_000_000) * harga_in + (token_out / 1_000_000) * harga_out
```

Cara menghemat:

- Batasi `max_tokens`
- Pangkas riwayat percakapan
- Pakai model kecil untuk tugas sederhana (klasifikasi, ekstraksi)
- Cache hasil untuk pertanyaan yang berulang

## Menangani kegagalan

Jaringan bisa putus, dan rate limit pasti kena cepat atau lambat.

```python
import time

def panggil_dengan_retry(fn, maks=3):
    for percobaan in range(maks):
        try:
            return fn()
        except Exception as e:
            if percobaan == maks - 1:
                raise
            time.sleep(2 ** percobaan)      # exponential backoff: 1s, 2s, 4s
```

Kode error yang perlu dikenali:

| Kode | Artinya | Tindakan |
|---|---|---|
| 401 | key salah | perbaiki key |
| 429 | rate limit | tunggu, backoff |
| 500/529 | masalah di server | retry |
| 400 | permintaan tidak valid | perbaiki payload |

Kode 429 dan 5xx layak di-retry; 400 dan 401 tidak — mengulanginya cuma membuang waktu.

## Checklist sebelum produksi

- [ ] API key dari environment variable, tidak pernah masuk repo
- [ ] `timeout` dipasang di setiap panggilan
- [ ] Retry dengan exponential backoff untuk 429/5xx
- [ ] `max_tokens` dibatasi
- [ ] Penguraian keluaran tahan terhadap format yang meleset
- [ ] Biaya dan jumlah panggilan dicatat
- [ ] Input pengguna dipisahkan dengan pembatas (prompt injection)
- [ ] Ada jalur cadangan kalau API mati

## Ringkasan

- Semua penyedia memakai format pesan role/content yang mirip.
- API key disimpan di environment variable, tidak pernah di kode.
- Riwayat percakapan kamu yang kelola, dan biayanya ikut bertambah.
- Retry dengan backoff untuk 429/5xx; jangan retry untuk 400/401.

## Kesalahan umum

- Menulis API key langsung di kode lalu ter-push ke GitHub.
- Memanggil API tanpa `timeout` sehingga program menggantung.
- Mengirim seluruh riwayat percakapan tanpa batas.
