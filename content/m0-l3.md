## Error itu petunjuk, bukan hukuman

Pemula sering panik lihat teks merah panjang. Padahal traceback Python itu **laporan investigasi** yang isinya justru sangat membantu — asal kamu tahu cara bacanya.

Aturan pertama: **baca dari bawah ke atas.**

```
Traceback (most recent call last):
  File "app.py", line 8, in <module>
    hasil = bagi(10, 0)
  File "app.py", line 5, in bagi
    return a / b
ZeroDivisionError: division by zero
```

| Bagian | Artinya |
|---|---|
| Baris **terakhir** | jenis error + penjelasan singkat — **baca ini duluan** |
| Baris di atasnya | baris kode yang benar-benar meledak |
| Baris lebih atas lagi | siapa yang memanggilnya (jejak perjalanan) |

Jadi bacanya: *"Terjadi pembagian nol, di baris 5 di dalam fungsi `bagi`, yang dipanggil dari baris 8."*

## Kamus error yang sering muncul

### `SyntaxError` — Python nggak ngerti tulisanmu

```python
print("halo"
```
```
SyntaxError: '(' was never closed
```

Penyebab tersering: kurang tutup kurung, kurang tanda kutip, atau kurang titik dua.

⚠️ Jebakan: Python kadang menunjuk baris **setelah** kesalahannya. Kalau baris yang ditunjuk kelihatan normal, periksa baris di atasnya.

### `NameError` — nama tidak dikenal

```python
print(nama)
```
```
NameError: name 'nama' is not defined
```

Penyebab: salah ketik nama variabel, atau memakai variabel sebelum dibuat.

### `TypeError` — tipe datanya nggak cocok

```python
"5" + 3
```
```
TypeError: can only concatenate str (not "int") to str
```

### `ValueError` — tipenya benar, nilainya salah

```python
int("abc")
```
```
ValueError: invalid literal for int() with base 10: 'abc'
```

### `IndentationError` — jorokan kacau

```python
if True:
print("halo")
```
```
IndentationError: expected an indented block
```

Sering terjadi karena mencampur **tab** dan **spasi**. Setel editormu untuk selalu memakai 4 spasi.

### `IndexError` / `KeyError` — data yang dicari tidak ada

```python
[1, 2][5]              # IndexError: list index out of range
{"a": 1}["b"]          # KeyError: 'b'
```

### `AttributeError` — method/atribut tidak ada

```python
"abc".push("d")
```
```
AttributeError: 'str' object has no attribute 'push'
```

Biasanya karena salah ingat nama method (di Python itu `append` untuk list, dan string tidak bisa diubah sama sekali).

## Resep debugging 5 langkah

Kalau kode tidak jalan, jangan langsung menebak-nebak. Ikuti ini berurutan:

1. **Baca baris terakhir traceback.** Jenis error-nya apa?
2. **Buka baris yang ditunjuk.** Lihat baris itu dan satu baris di atasnya.
3. **Cetak isinya.** Tambahkan `print()` untuk melihat nilai sebenarnya:
   ```python
   print("DEBUG:", type(umur), repr(umur))
   ```
   `repr()` menampilkan bentuk mentahnya, jadi `"20"` (string) terlihat beda dari `20` (angka).
4. **Sederhanakan.** Potong kodenya sampai tersisa bagian terkecil yang masih error.
5. **Cari di internet.** Salin **baris terakhir** traceback-nya (buang nama file dan path pribadimu) lalu tempel ke mesin pencari.

Langkah 3 itu yang paling sering menyelesaikan masalah. Kebanyakan bug bukan karena kodemu salah tulis, tapi karena **isi variabelnya tidak seperti yang kamu kira**.

## Membaca dokumentasi

Dokumentasi resmi Python ada di [docs.python.org](https://docs.python.org/3/). Tapi cara tercepat mengecek sesuatu justru dari dalam Python sendiri:

```python
help(str.split)       # penjelasan lengkap
dir(str)              # daftar semua method milik string
type(x)               # x ini sebenarnya apa?
```

Membaca tanda tangan fungsi:

```
str.split(sep=None, maxsplit=-1)
```

Artinya `split` menerima dua argumen, keduanya **opsional** (punya nilai default). Jadi `"a,b".split()` dan `"a,b".split(",")` dua-duanya sah.

Sedangkan:

```
round(number, ndigits=None)
```

`number` **wajib** (tidak ada tanda `=`), `ndigits` opsional.

## Bertanya dengan benar

Kalau sudah mentok dan mau bertanya (ke forum, teman, atau AI), sertakan empat hal ini:

1. **Apa yang ingin kamu capai** — tujuannya, bukan cuma kodenya
2. **Kode terkecil yang masih error** — bukan seluruh file 300 baris
3. **Traceback lengkap** — disalin apa adanya, bukan diketik ulang atau difoto
4. **Yang sudah kamu coba** — supaya tidak diberi saran yang sudah gagal

Pertanyaan yang disusun begini sering terjawab sendiri saat kamu menulisnya. Fenomena ini dikenal sebagai *rubber duck debugging*: menjelaskan masalah dengan runtut memaksa otakmu melihat celah yang tadi terlewat.

## Latihan mandiri

<div class="latihan"><b>Latihan 1.</b> Error apa yang muncul dari <code>int("3.5")</code>, dan kenapa bukan SyntaxError?</div>

<details>
<summary>Lihat jawaban</summary>

`ValueError`. Tulisannya sah secara sintaks — Python paham maksudmu memanggil `int()` dengan sebuah string. Yang bermasalah adalah **isinya**: `"3.5"` bukan bilangan bulat.

SyntaxError hanya muncul kalau Python tidak bisa membaca tulisannya sama sekali, misalnya `int("3.5"` (kurang tutup kurung).
</details>

<div class="latihan"><b>Latihan 2.</b> Kamu yakin variabel <code>umur</code> berisi angka 20, tapi <code>umur + 5</code> menghasilkan TypeError. Satu baris apa yang kamu tambahkan untuk memastikan?</div>

<details>
<summary>Lihat jawaban</summary>

```python
print(type(umur), repr(umur))
```

Kemungkinan besar hasilnya `<class 'str'> '20'` — isinya string, bukan angka. Ini terjadi kalau nilainya datang dari `input()`, file, atau CSV.

Perbaikannya: `umur = int(umur)`.
</details>

<div class="latihan"><b>Latihan 3.</b> Baca traceback ini. Di baris berapa kesalahannya, dan apa penyebabnya?
<pre>Traceback (most recent call last):
  File "main.py", line 12, in &lt;module&gt;
    tampilkan(data)
  File "main.py", line 7, in tampilkan
    print(d["nama"])
KeyError: 'nama'</pre></div>

<details>
<summary>Lihat jawaban</summary>

Kesalahannya di **baris 7**, di dalam fungsi `tampilkan`. Baris 12 cuma pemanggilnya.

Penyebabnya: dictionary `d` tidak punya kunci `"nama"`. Bisa jadi kuncinya bernama lain (`"name"`?), atau data itu memang tidak lengkap.

Langkah berikutnya: `print(d.keys())` tepat sebelum baris 7 untuk melihat kunci apa saja yang sebenarnya ada.
</details>

## Ringkasan

- Baca traceback **dari bawah**: jenis error dulu, baru lokasi, baru jejak pemanggilnya.
- `SyntaxError` = salah tulis, `NameError` = nama tak dikenal, `TypeError` = tipe salah, `ValueError` = nilai salah.
- Resep debugging: baca error → buka barisnya → `print(type(x), repr(x))` → sederhanakan → cari.
- `help()` dan `dir()` memberi dokumentasi langsung dari dalam Python.
- Pertanyaan yang baik memuat tujuan, kode minimal, traceback lengkap, dan yang sudah dicoba.

## Kesalahan umum

- Membaca traceback dari atas lalu bingung.
- Menyalin seluruh file saat bertanya, bukan bagian yang error.
- Menebak-nebak isi variabel alih-alih mencetaknya.
- Mengabaikan `IndentationError` yang sebenarnya cuma campuran tab dan spasi.
