## Tiga cara "melakukan banyak hal sekaligus"

Bayangin kamu masak sambil nunggu air mendidih. Kamu nggak berdiri diam menatap panci — kamu potong bawang sambil nunggu. Itu inti concurrency.

| Cara | Cocok untuk | Analogi |
|---|---|---|
| `threading` | I/O-bound | satu koki mengerjakan tugas lain selama nunggu |
| `multiprocessing` | CPU-bound | menambah koki (dan kompor) |
| `asyncio` | I/O-bound, jumlah besar | satu koki sangat terorganisir |

### I/O-bound vs CPU-bound

- **I/O-bound** = kebanyakan waktunya *menunggu*: request HTTP, baca file, query database. Ini mayoritas kerjaan saat memanggil API model AI.
- **CPU-bound** = kebanyakan waktunya *menghitung*: resize gambar, enkripsi, training model.

Aturan praktis: menunggu → `asyncio` atau `threading`. Menghitung → `multiprocessing`.

## Kenapa threading tidak mempercepat perhitungan?

Python punya **GIL** (Global Interpreter Lock): dalam satu proses, hanya satu thread yang boleh menjalankan bytecode Python pada satu waktu. Jadi 4 thread tidak membuat perhitungan 4x lebih cepat. Tapi saat sebuah thread **menunggu** I/O, GIL dilepas — di situlah threading membantu.

`multiprocessing` menghindari GIL dengan menjalankan beberapa proses Python terpisah (masing-masing punya GIL sendiri).

## `async` / `await`

```python
import asyncio

async def ambil(x):
    await asyncio.sleep(1)     # pura-pura request jaringan
    return x * 2

async def main():
    hasil = await ambil(5)
    print(hasil)               # 10

asyncio.run(main())
```

- `async def` membuat **coroutine** — memanggilnya tidak langsung menjalankan isinya.
- `await` berarti *"ini butuh waktu; silakan kerjakan yang lain dulu"*.
- `asyncio.run()` menyalakan event loop dan menjalankan coroutine utama.

## `gather` — menjalankan bersamaan

Ini bagian pentingnya. Berurutan:

```python
async def main():
    a = await ambil(1)      # tunggu 1 detik
    b = await ambil(2)      # tunggu 1 detik lagi
    return [a, b]           # total ~2 detik
```

Bersamaan:

```python
async def main():
    return await asyncio.gather(ambil(1), ambil(2))   # total ~1 detik
```

Dengan daftar dinamis:

```python
async def ambil_semua(nilai):
    return await asyncio.gather(*[ambil(x) for x in nilai])

# asyncio.run(ambil_semua([1, 2, 3]))  ->  [2, 4, 6]
```

`gather` mengembalikan hasil dalam **urutan argumennya**, bukan urutan selesainya. Untuk 100 request HTTP, bedanya bisa dari 100 detik menjadi 2 detik.

## Aturan main asyncio

- `await` hanya boleh di dalam `async def`.
- Jangan memakai fungsi blocking (`time.sleep`, `requests.get`) di dalam coroutine — itu membekukan seluruh event loop. Pakai padanan async-nya (`asyncio.sleep`, `httpx`, `aiohttp`).
- Memanggil `ambil(5)` tanpa `await` cuma menghasilkan objek coroutine yang tidak pernah jalan.

## Ringkasan

- I/O-bound → asyncio/threading; CPU-bound → multiprocessing.
- GIL membuat threading tidak mempercepat perhitungan murni.
- `async def` + `await` menandai titik tunggu.
- `asyncio.gather` menjalankan banyak coroutine bersamaan.

## Kesalahan umum

- Memakai `time.sleep()` di dalam coroutine.
- Lupa `await` sehingga coroutine tidak pernah dieksekusi.
- Memakai multiprocessing untuk pekerjaan yang sebenarnya cuma menunggu jaringan.
