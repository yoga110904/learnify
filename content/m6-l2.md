## Masalah: test yang copy-paste

```python
def test_diskon_10():
    assert diskon(100, 10) == 90

def test_diskon_20():
    assert diskon(100, 20) == 80

def test_diskon_50():
    assert diskon(100, 50) == 50
# ... dan seterusnya
```

Logikanya sama persis, cuma angkanya beda. Kalau formula diskon berubah, kamu edit lima tempat.

## `@pytest.mark.parametrize`

```python
import pytest

@pytest.mark.parametrize("harga, persen, harapan", [
    (100, 10, 90),
    (100, 20, 80),
    (100, 50, 50),
    (100, 0, 100),
    (0, 10, 0),
])
def test_diskon(harga, persen, harapan):
    assert diskon(harga, persen) == harapan
```

Satu fungsi, lima test. pytest melaporkannya terpisah:

```
test_diskon[100-10-90] PASSED
test_diskon[100-20-80] PASSED
test_diskon[0-10-0]    PASSED
```

Kalau satu kasus gagal, kamu langsung tahu kombinasi mana yang bermasalah — beda dengan loop `for` di dalam satu test, yang berhenti di kegagalan pertama.

Menambah kasus uji sekarang = menambah satu baris data.

Kasih nama supaya laporannya terbaca:

```python
@pytest.mark.parametrize("pw, valid", [
    ("abc", False),
    ("abcdefgh", True),
], ids=["terlalu-pendek", "panjang-cukup"])
def test_password(pw, valid):
    assert cek_password(pw) is valid
```

## Fixture: menyiapkan bahan test

Banyak test butuh persiapan yang sama: koneksi database, user contoh, browser terbuka. **Fixture** menyiapkannya sekali lalu "menyuntikkannya" ke test yang meminta.

```python
import pytest

@pytest.fixture
def user():
    return {"nama": "Salsa", "role": "qa"}

def test_nama(user):          # cukup tulis namanya sebagai parameter
    assert user["nama"] == "Salsa"

def test_role(user):          # tiap test dapat objek segar
    assert user["role"] == "qa"
```

### Setup dan teardown dengan `yield`

```python
@pytest.fixture
def browser():
    b = buka_browser()        # setup
    yield b                   # test dijalankan di sini
    b.close()                 # teardown — selalu jalan
```

Polanya persis context manager di Modul 5.

### Scope fixture

```python
@pytest.fixture(scope="function")   # default: baru untuk tiap test
@pytest.fixture(scope="class")
@pytest.fixture(scope="module")     # sekali per file
@pytest.fixture(scope="session")    # sekali untuk seluruh sesi pytest
```

Pilih yang paling sempit yang masih masuk akal. Fixture `session` yang bisa diubah test bikin test saling mempengaruhi — pelanggaran prinsip *Independent*.

### `conftest.py`

Fixture yang ditaruh di `conftest.py` otomatis tersedia untuk semua test di folder itu dan subfoldernya — tanpa import.

```
tests/
├── conftest.py        <- fixture browser, base_url, data user
├── test_login.py
└── test_checkout.py
```

## Marker: memberi label test

```python
@pytest.mark.slow
def test_laporan_besar(): ...

@pytest.mark.skip(reason="fitur belum rilis")
def test_fitur_baru(): ...

@pytest.mark.xfail(reason="bug #123 belum diperbaiki")
def test_bug_diketahui(): ...
```

```bash
pytest -m "not slow"     # jalankan semua kecuali yang lambat
```

Daftarkan marker di `pytest.ini` supaya tidak muncul peringatan:

```ini
[pytest]
markers =
    slow: test yang lama
```

## Ringkasan

- `parametrize` mengubah banyak test serupa jadi satu fungsi + tabel data.
- Fixture menyiapkan bahan test dan membereskannya lewat `yield`.
- Scope fixture menentukan seberapa sering ia dibuat ulang.
- Marker memberi label agar test bisa dipilih atau dilewati.

## Kesalahan umum

- Menaruh banyak kasus dalam satu `for` di dalam test — laporan gagalnya tidak informatif.
- Memakai fixture scope `session` untuk data yang diubah test.
- Lupa `yield` sehingga teardown tidak pernah jalan.
