## Masalah nyata di automation testing

Bayangin kamu punya 30 test yang semuanya login dulu:

```python
def test_login_sukses():
    driver.isi("#user", "admin")
    driver.isi("#pw", "rahasia")
    driver.klik("#submit")

def test_login_gagal():
    driver.isi("#user", "salah")
    driver.isi("#pw", "salah")
    driver.klik("#submit")
# ... 28 test lain dengan selector yang sama
```

Lalu developer mengganti `id="user"` menjadi `id="username"`. Kamu harus memperbaiki **30 file**. Ini bukan skenario karangan — ini alasan nomor satu framework test jadi ditinggalkan.

## Solusinya: Page Object Model (POM)

Satu class untuk satu halaman. Class itu yang menyimpan selector dan menyediakan aksi bermakna. Test hanya bicara "apa", bukan "bagaimana".

```python
class LoginPage:
    # selector dikumpulkan di satu tempat
    INPUT_USER = "#user"
    INPUT_PW = "#pw"
    BTN_SUBMIT = "#submit"

    def __init__(self, driver):
        self.driver = driver

    def login(self, user, pw):
        self.driver.isi(self.INPUT_USER, user)
        self.driver.isi(self.INPUT_PW, pw)
        self.driver.klik(self.BTN_SUBMIT)
        return self            # biar bisa dirangkai
```

Test-nya jadi:

```python
def test_login_sukses(driver):
    LoginPage(driver).login("admin", "rahasia")
    assert driver.url_sekarang() == "/dashboard"
```

Sekarang kalau selector berubah, kamu cuma edit **satu baris di satu file**.

## OOP mana yang kepakai di sini?

| Konsep | Wujudnya di POM |
|---|---|
| Class & object | satu class per halaman |
| Encapsulation | selector dan `driver` disimpan di dalam class |
| Inheritance | `BasePage` berisi aksi umum untuk semua halaman |
| Polymorphism | tiap halaman punya `buka()` versinya sendiri |

```python
class BasePage:
    URL = "/"

    def __init__(self, driver):
        self.driver = driver

    def buka(self):
        self.driver.pergi(self.URL)
        return self


class LoginPage(BasePage):
    URL = "/login"
    INPUT_USER = "#user"
    ...
```

## Aturan main POM yang baik

1. **Page object tidak boleh berisi assert.** Dia menyediakan aksi dan data; penilaian benar/salah ada di test.
2. **Satu method = satu aksi yang berarti bagi user** (`login`, `tambah_ke_keranjang`), bukan `klik_tombol_biru`.
3. **Method mengembalikan page object** halaman tujuan, supaya alurnya terbaca:
   ```python
   DashboardPage(driver) == LoginPage(driver).login("a", "b")
   ```
4. **Selector jadi konstanta class**, bukan disebar di tengah method.

## Test double (driver palsu)

Buat latihan, kita nggak butuh browser sungguhan. Berkat duck typing, kita bisa bikin objek yang cuma **mencatat** apa yang dipanggil:

```python
class DriverPalsu:
    def __init__(self):
        self.aksi = []
    def isi(self, sel, teks):
        self.aksi.append(("isi", sel, teks))
    def klik(self, sel):
        self.aksi.append(("klik", sel))

d = DriverPalsu()
LoginPage(d).login("a", "b")
print(d.aksi)
# [('isi', '#user', 'a'), ('isi', '#pw', 'b'), ('klik', '#submit')]
```

Kita jadi bisa menguji bahwa urutan aksinya benar — tanpa browser, tanpa internet, dalam milidetik. Teknik ini namanya **mocking**, dan dibahas penuh di Modul 6.

## Ringkasan

- POM memindahkan selector dari test ke class per halaman.
- Perubahan UI cukup diperbaiki di satu tempat.
- Page object berisi aksi, bukan assertion.
- Driver palsu memungkinkan menguji alur tanpa browser sungguhan.

## Kesalahan umum

- Menaruh `assert` di dalam page object.
- Membuat method sekelas `klik_tombol_x` yang hanya membungkus satu klik tanpa makna.
- Menulis selector langsung di file test "biar cepat".
