## Ujian dengan bocoran soal

Bayangkan guru memberi ujian yang soalnya persis sama dengan latihan. Semua dapat 100. Apakah itu artinya mereka paham? Belum tentu — mungkin cuma hafal.

Menguji model dengan data yang dipakai melatihnya adalah kesalahan yang sama.

```python
model.fit(X, y)
model.score(X, y)      # 0.99  ← angka yang menipu
```

## Train/test split

Sisihkan sebagian data, jangan biarkan model melihatnya saat latihan.

```python
from sklearn.model_selection import train_test_split

X_train, X_test, y_train, y_test = train_test_split(
    X, y,
    test_size=0.2,        # 20% untuk ujian
    random_state=42,      # supaya hasilnya bisa diulang
    stratify=y            # jaga proporsi kelas tetap sama
)

model.fit(X_train, y_train)
print(model.score(X_test, y_test))    # ← angka yang jujur
```

Tiga parameter itu semuanya penting:

- `random_state` membuat pembagiannya konsisten, jadi eksperimenmu bisa dibandingkan
- `stratify=y` wajib untuk klasifikasi tidak seimbang — tanpa itu, data uji bisa kebetulan tidak punya kelas minoritas sama sekali
- `test_size` umumnya 0,2 atau 0,3

## Overfitting vs underfitting

| Kondisi | Skor latih | Skor uji | Artinya |
|---|---|---|---|
| **Underfitting** | rendah | rendah | model terlalu sederhana |
| **Pas** | tinggi | tinggi | 🎯 |
| **Overfitting** | tinggi | rendah | model menghafal, bukan belajar |

```python
print("latih:", model.score(X_train, y_train))   # 0.99
print("uji:  ", model.score(X_test, y_test))     # 0.62  ← overfitting
```

Selisih besar antara keduanya adalah sinyal paling jelas.

### Mengatasi overfitting

- Tambah data latih (paling ampuh)
- Sederhanakan model (`max_depth` lebih kecil, fitur lebih sedikit)
- Tambah regularisasi (Ridge, Lasso, `alpha` lebih besar)
- Hentikan pelatihan lebih awal

### Mengatasi underfitting

- Pakai model yang lebih kuat
- Tambah fitur atau buat fitur turunan
- Kurangi regularisasi

## Cross-validation

Satu kali split bisa untung-untungan — bagaimana kalau kebetulan data ujinya mudah? **K-fold cross-validation** membagi data jadi k bagian, lalu melatih k kali dengan bagian uji yang berbeda-beda.

```python
from sklearn.model_selection import cross_val_score

skor = cross_val_score(model, X, y, cv=5)
print(skor)              # [0.82 0.79 0.85 0.81 0.80]
print(skor.mean(), skor.std())
```

Rata-ratanya jauh lebih dipercaya daripada satu angka. Dan **standar deviasinya** juga penting: kalau skornya `[0.95, 0.60, 0.88]`, modelmu tidak stabil.

## Validation set

Kalau kamu mencoba banyak konfigurasi dan memilih yang terbaik **berdasarkan data uji**, kamu diam-diam overfit ke data uji itu. Solusinya tiga bagian:

```
60% train      → melatih model
20% validation → memilih hyperparameter
20% test       → dipakai SEKALI di akhir
```

Data uji adalah ujian terakhir. Dipakai sekali, jangan diintip berulang-ulang.

## Data leakage

Kesalahan paling mahal di ML: informasi dari data uji bocor ke proses pelatihan.

```python
# ❌ SALAH — scaler belajar dari seluruh data
scaler.fit(X)
X_train, X_test = train_test_split(scaler.transform(X))

# ✅ BENAR — scaler hanya belajar dari data latih
X_train, X_test = train_test_split(X)
scaler.fit(X_train)
X_train = scaler.transform(X_train)
X_test = scaler.transform(X_test)      # transform saja, tanpa fit
```

Gejalanya: skormu luar biasa bagus saat eksperimen, lalu hancur di produksi.

## Ringkasan

- Selalu uji model dengan data yang belum pernah dilihatnya.
- Skor latih tinggi + skor uji rendah = overfitting.
- Cross-validation memberi estimasi yang lebih dipercaya beserta kestabilannya.
- `fit` hanya pada data latih; data uji cuma di-`transform`.

## Kesalahan umum

- Melaporkan skor dari data latih.
- Lupa `stratify=y` pada data yang kelasnya timpang.
- Menjalankan scaler pada seluruh data sebelum split.
