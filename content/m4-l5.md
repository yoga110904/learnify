## Kenapa objekmu tercetak jelek?

```python
class Produk:
    def __init__(self, nama, harga):
        self.nama = nama
        self.harga = harga

print(Produk("Kopi", 20))
# <__main__.Produk object at 0x7f8b1c0d5e50>   😒
```

Python nggak tahu cara menampilkan objek buatanmu — kecuali kamu yang memberitahu, lewat **dunder method** (double underscore, `__nama__`). Ini "colokan" resmi supaya objekmu berperilaku seperti tipe bawaan.

## `__str__` dan `__repr__`

```python
class Produk:
    def __init__(self, nama, harga):
        self.nama = nama
        self.harga = harga

    def __str__(self):
        return f"{self.nama} (Rp{self.harga})"

    def __repr__(self):
        return f"Produk({self.nama!r}, {self.harga!r})"

p = Produk("Kopi", 20)
print(p)        # Kopi (Rp20)        <- __str__ : untuk manusia
print([p])      # [Produk('Kopi', 20)]  <- __repr__ : untuk developer
```

Pedoman: `__str__` enak dibaca user, `__repr__` sebaiknya bisa ditempel kembali ke kode. Kalau cuma mau bikin satu, bikin `__repr__` (dia jadi cadangan `__str__`).

## `__eq__` — dua objek dianggap sama

```python
Produk("Kopi", 20) == Produk("Kopi", 20)   # False! 😱
```

Secara default Python membandingkan **alamat memori**, bukan isi. Perbaiki:

```python
    def __eq__(self, other):
        if not isinstance(other, Produk):
            return NotImplemented
        return (self.nama, self.harga) == (other.nama, other.harga)
```

## Dunder lain yang sering dipakai

```python
    def __len__(self):            # len(objek)
        return len(self.item)

    def __lt__(self, other):      # objek < objek, dipakai sorted()
        return self.harga < other.harga

    def __getitem__(self, i):     # objek[i]
        return self.item[i]

    def __contains__(self, x):    # x in objek
        return x in self.item
```

Cukup dengan `__lt__`, fungsi `sorted()` sudah bisa mengurutkan objekmu.

## `@dataclass` — jalan pintas

Menulis `__init__`, `__repr__`, dan `__eq__` secara manual itu melelahkan. Sejak Python 3.7 ada `dataclass`:

```python
from dataclasses import dataclass, field

@dataclass
class Produk:
    nama: str
    harga: int

p = Produk("Kopi", 20)
print(p)                              # Produk(nama='Kopi', harga=20)
print(p == Produk("Kopi", 20))        # True
```

Satu dekorator menggantikan puluhan baris.

### Opsi yang berguna

```python
@dataclass(order=True)        # ikut membuat __lt__, __gt__, dst.
class Produk:
    harga: int                # urutan field menentukan urutan perbandingan
    nama: str

sorted([Produk(5, "b"), Produk(2, "a")])[0].nama    # 'a'
```

```python
@dataclass(frozen=True)       # objek jadi immutable (dan hashable)
class Titik:
    x: int
    y: int
```

Default berupa list harus memakai `field`:

```python
@dataclass
class Keranjang:
    item: list = field(default_factory=list)   # ✅
    # item: list = []   ❌ error — sama seperti jebakan default argument
```

## Ringkasan

- Dunder method membuat objekmu berperilaku seperti tipe bawaan.
- `__str__` untuk user, `__repr__` untuk developer.
- `__eq__` membandingkan isi; `__lt__` membuat objek bisa di-`sorted()`.
- `@dataclass` otomatis membuat `__init__`, `__repr__`, dan `__eq__`.

## Kesalahan umum

- Membandingkan objek tanpa `__eq__` lalu heran hasilnya `False`.
- Memakai `[]` sebagai default field dataclass (harus `field(default_factory=list)`).
- Lupa `order=True` saat ingin objek dataclass bisa diurutkan.
