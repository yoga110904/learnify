## `with` itu sebenarnya apa?

Kamu sudah memakainya di Modul 3:

```python
with open("data.txt") as f:
    isi = f.read()
# file otomatis tertutup di sini, bahkan kalau terjadi error
```

`with` adalah **context manager**: mekanisme "siapkan sesuatu → pakai → pasti dibereskan".

Tanpa `with`, kode yang setara harus ditulis begini:

```python
f = open("data.txt")
try:
    isi = f.read()
finally:
    f.close()
```

## Membuat context manager sendiri (gaya class)

Butuh dua method: `__enter__` dan `__exit__`.

```python
import time

class Timer:
    def __enter__(self):
        self.mulai = time.perf_counter()
        return self                 # nilai yang masuk ke "as t"

    def __exit__(self, exc_type, exc_value, traceback):
        self.durasi = time.perf_counter() - self.mulai
        return False                # False = error tetap dilempar

with Timer() as t:
    total = sum(range(100000))

print(f"{t.durasi:.4f} detik")
```

Yang perlu dipahami:

- Nilai yang di-`return` oleh `__enter__` adalah yang diterima variabel setelah `as`.
- `__exit__` **selalu** dijalankan, termasuk saat ada exception.
- Tiga parameter `__exit__` berisi info exception (atau `None` semua kalau mulus).
- `return True` di `__exit__` berarti *"error sudah saya tangani, jangan dilempar"*. Hati-hati: ini bisa menyembunyikan bug.

## Gaya generator dengan `@contextmanager`

Lebih ringkas untuk kasus sederhana:

```python
from contextlib import contextmanager
import time

@contextmanager
def timer():
    mulai = time.perf_counter()
    try:
        yield                       # di sini blok with dijalankan
    finally:
        print(f"{time.perf_counter() - mulai:.4f} detik")

with timer():
    sum(range(100000))
```

Polanya: setup → `yield` → cleanup di `finally`.

## Contoh yang kepakai sehari-hari

Koneksi database:

```python
@contextmanager
def koneksi(db):
    conn = buka(db)
    try:
        yield conn
    finally:
        conn.close()
```

Pindah folder sementara, membuat file sementara, mematikan log sementara, memuat model AI ke memori lalu melepasnya — semuanya pola yang sama.

Beberapa context manager sekaligus:

```python
with open("a.txt") as a, open("b.txt", "w") as b:
    b.write(a.read())
```

Dan dari `contextlib`:

```python
from contextlib import suppress

with suppress(FileNotFoundError):
    os.remove("mungkin_tidak_ada.txt")
```

## Ringkasan

- Context manager menjamin cleanup dijalankan, ada error atau tidak.
- Gaya class: `__enter__` dan `__exit__`.
- Gaya generator: `@contextmanager` dengan `yield` di dalam `try/finally`.
- Nilai `return` dari `__enter__` adalah yang diterima setelah `as`.

## Kesalahan umum

- Lupa `try/finally` di `@contextmanager` sehingga cleanup dilewati saat error.
- `return True` di `__exit__` tanpa sadar menelan semua exception.
- Membuka resource tanpa `with` lalu lupa menutupnya.
