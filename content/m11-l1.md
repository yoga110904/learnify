## Mesin penebak kata berikutnya

ChatGPT, Claude, dan Gemini terasa ajaib. Padahal intinya satu kalimat:

> **Model bahasa memprediksi token berikutnya yang paling mungkin, lalu mengulanginya.**

```
"Ibu kota Indonesia adalah" → [Jakarta: 0.94, kota: 0.02, ...]
```

Pilih "Jakarta", tempelkan ke kalimat, prediksi lagi. Begitu terus sampai berhenti.

Semua kemampuan yang tampak "cerdas" — meringkas, menerjemahkan, menulis kode — muncul dari melakukan satu tugas ini dengan sangat baik, pada data yang sangat banyak.

## Token, bukan kata

Model tidak melihat huruf atau kata. Dia melihat **token** — potongan teks yang sering muncul bersama.

```
"belajar"     → ["belajar"]            1 token
"pembelajaran"→ ["pem", "belajar", "an"]  3 token
"Halo dunia!" → ["Halo", " dunia", "!"]   3 token
```

Aturan kasarnya: **1 token ≈ 4 karakter ≈ 0,75 kata** dalam bahasa Inggris. Bahasa Indonesia biasanya butuh lebih banyak token untuk teks yang sama, jadi biayanya sedikit lebih mahal.

Ini menjelaskan beberapa keanehan model:

- Sulit menghitung huruf dalam kata ("berapa huruf r di 'strawberry'?") — karena dia tidak melihat huruf
- Angka panjang sering salah — karena terpecah jadi token yang aneh
- Harga API dihitung per token, bukan per kata

## Context window

Batas berapa token yang bisa "dilihat" model sekaligus — mencakup prompt **dan** jawabannya.

| Model | Perkiraan konteks |
|---|---|
| GPT-3.5 | 16 ribu token |
| Model modern | 128 ribu – 1 juta token |

Kalau percakapan melebihi batas, bagian paling awal dipotong. Itulah kenapa chatbot bisa "lupa" apa yang kamu bilang di awal percakapan yang sangat panjang.

Penting dipahami: **model tidak punya ingatan antar percakapan.** Setiap permintaan mengirim ulang seluruh riwayat. Yang terasa seperti "ingat" sebenarnya adalah teks lama yang dikirim ulang.

## Temperature

Model menghasilkan peluang untuk tiap token. Bagaimana memilihnya?

```python
peluang = {"Jakarta": 0.94, "Bandung": 0.03, "Surabaya": 0.02}
```

- **temperature = 0** → selalu ambil yang tertinggi. Konsisten, bisa diulang. Untuk ekstraksi data, klasifikasi, kode.
- **temperature = 0,7** → sampling acak berbobot. Lebih bervariasi. Untuk menulis kreatif.
- **temperature = 2** → hampir acak, sering ngawur.

Parameter terkait: `top_p` (ambil dari sekumpulan token teratas yang totalnya p) dan `max_tokens` (batas panjang jawaban).

## Kenapa model berhalusinasi?

Karena tugasnya **menghasilkan teks yang masuk akal**, bukan teks yang benar. Kalau tidak tahu jawabannya, dia tetap menghasilkan kalimat yang terdengar meyakinkan — sebab itulah kelanjutan yang paling "mungkin" secara statistik.

Cara menguranginya:

- Berikan sumber informasinya di dalam prompt (**RAG** — dibahas nanti)
- Minta model menyebut "tidak tahu" kalau informasinya tidak ada
- Turunkan temperature untuk tugas faktual
- Verifikasi keluaran untuk hal yang penting

Halusinasi bukan bug yang bisa ditambal — ini sifat bawaan cara kerjanya. Desain sistemmu harus memperhitungkannya.

## Tiga tahap pelatihan

1. **Pre-training** — belajar memprediksi token berikutnya dari teks internet dalam jumlah raksasa. Mahal, butuh ribuan GPU berbulan-bulan.
2. **Fine-tuning** — dilatih pada contoh percakapan agar bisa mengikuti instruksi.
3. **RLHF** — manusia memberi peringkat pada jawaban; model dilatih agar lebih disukai, jujur, dan aman.

Tahap 1 memberi pengetahuan. Tahap 2 dan 3 memberi kesopanan dan kepatuhan.

## Ringkasan

- LLM memprediksi token berikutnya, diulang terus-menerus.
- Token adalah potongan teks; ±1 token = 4 karakter.
- Context window membatasi prompt + jawaban, dan model tidak punya ingatan antar sesi.
- Temperature rendah untuk tugas faktual, tinggi untuk kreatif.

## Kesalahan umum

- Mengira model "mencari" jawaban di internet saat menjawab.
- Memakai temperature tinggi untuk ekstraksi data.
- Mempercayai jawaban faktual tanpa memberi sumber atau memverifikasinya.
