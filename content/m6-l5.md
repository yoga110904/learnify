## Kenapa Playwright?

Selenium sudah lama jadi standar, tapi Playwright (dari Microsoft) menyelesaikan keluhan terbesar UI testing: **flaky test**.

| | Selenium | Playwright |
|---|---|---|
| Menunggu elemen | `sleep` / explicit wait manual | auto-wait bawaan |
| Instalasi browser | atur driver sendiri | `playwright install` |
| Multi-browser | perlu driver masing-masing | Chromium, Firefox, WebKit sekaligus |
| Debug | screenshot manual | trace viewer dengan rekaman langkah |

## Locator dan auto-wait

Ini konsep terpentingnya. `page.locator(...)` tidak langsung mencari elemen — ia menunggu sampai elemennya **ada, terlihat, dan siap diklik**, baru beraksi.

```python
page.get_by_role("button", name="Masuk").click()
page.get_by_label("Email").fill("a@b.com")
page.get_by_text("Selamat datang")
page.get_by_placeholder("Cari...")
page.get_by_test_id("submit")        # data-testid
page.locator("#user")                # CSS kalau terpaksa
```

Urutan prioritas locator: **role → label → text → test-id → CSS/XPath**. Yang di atas meniru cara user asli menemukan elemen, jadi tidak gampang rusak saat struktur HTML berubah.

```python
# ❌ sumber flaky
time.sleep(3)
page.click("#submit")

# ✅ auto-wait
page.get_by_role("button", name="Kirim").click()
```

## Assertion

```python
from playwright.sync_api import expect

expect(page.get_by_text("Berhasil")).to_be_visible()
expect(page).to_have_url("https://app.com/dashboard")
expect(page.get_by_role("listitem")).to_have_count(3)
```

`expect` juga punya retry bawaan: ia mencoba ulang selama beberapa detik sebelum menyatakan gagal. Jangan pakai `assert` biasa untuk kondisi UI yang butuh waktu muncul.

## Debug: screenshot dan trace

```bash
pytest --screenshot=only-on-failure --video=retain-on-failure --tracing=retain-on-failure
playwright show-trace trace.zip
```

Trace viewer memutar ulang seluruh test: tiap langkah, snapshot DOM, request jaringan, dan console. Ini alat paling berguna saat test gagal hanya di CI.

## Menjalankan di GitHub Actions

`.github/workflows/test.yml`:

```yaml
name: E2E Tests
on: [push, pull_request]

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
      - run: pip install -r requirements.txt
      - run: playwright install --with-deps chromium
      - run: pytest --html=report.html --self-contained-html
      - uses: actions/upload-artifact@v4
        if: always()
        with:
          name: laporan
          path: report.html
```

`if: always()` penting — laporan justru paling dibutuhkan saat test gagal.

## Checklist tugas mandiri

1. Buat folder proyek baru + `venv` + `requirements.txt`.
2. `pip install pytest pytest-playwright pytest-html` lalu `playwright install`.
3. Pilih situs latihan: `saucedemo.com` atau `the-internet.herokuapp.com`.
4. Buat `pages/` berisi minimal 3 page object.
5. Tulis minimal 10 test UI — termasuk jalur gagal (login salah, field kosong).
6. Pakai fixture di `conftest.py` dan minimal satu `parametrize`.
7. Jalankan `pytest --html=report.html` dan pastikan hijau.
8. Push ke GitHub dan aktifkan workflow di atas.

Checklist ini juga menjadi bagian penilaian Proyek Akhir.

## Ringkasan

- Auto-wait Playwright menghapus `sleep` manual dan mengurangi test flaky.
- Prioritaskan locator berbasis role/label daripada CSS/XPath.
- `expect()` punya retry bawaan; `assert` biasa tidak.
- Trace viewer dan laporan HTML adalah alat debugging utama di CI.

## Kesalahan umum

- Memakai `time.sleep()` untuk "menunggu" elemen.
- Locator berbasis CSS panjang yang langsung rusak saat UI diubah.
- Tidak menyimpan artefak laporan di CI sehingga kegagalan sulit ditelusuri.
