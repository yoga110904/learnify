## Tiga alat wajib sebelum proyek beneran

Lesson ini teori — tapi tanpa tiga hal ini, proyek Python kamu bakal berantakan begitu keluar dari satu file.

## 1. pip — pemasang library

`pip` adalah aplikasi pemasang paket bawaan Python.

```bash
pip install requests           # pasang
pip install requests==2.31.0   # versi tertentu
pip install -U requests        # upgrade
pip uninstall requests         # copot
pip list                       # lihat yang terpasang
```

### `requirements.txt`

Daftar library yang dibutuhkan proyek, supaya orang lain (dan server CI) bisa memasang hal yang persis sama:

```
requests==2.31.0
pytest==8.2.0
playwright==1.44.0
```

```bash
pip freeze > requirements.txt    # simpan kondisi sekarang
pip install -r requirements.txt  # pasang dari daftar
```

File ini **wajib** ikut di repo. Proyek akhir kamu nanti dinilai dari keberadaannya juga.

## 2. Virtual environment — kotak terpisah per proyek

Masalahnya: Proyek A butuh `requests` versi 2.20, Proyek B butuh versi 2.31. Kalau dipasang global, mereka rebutan.

**venv** membuat folder berisi Python + library khusus untuk satu proyek.

```bash
python -m venv venv          # bikin

source venv/bin/activate     # aktifkan (Mac/Linux)
venv\Scripts\activate        # aktifkan (Windows)

deactivate                   # keluar
```

Kalau aktif, prompt terminal diawali `(venv)`. Semua `pip install` setelah itu masuk ke kotak proyek ini saja.

Tambahkan `venv/` ke `.gitignore` — folder itu besar dan bisa dibuat ulang dari `requirements.txt`.

## 3. Git — mesin waktu untuk kode

```bash
git init                      # mulai melacak folder ini
git status                    # apa saja yang berubah
git add .                     # siapkan semua perubahan
git commit -m "tambah fitur login"   # simpan snapshot
git log --oneline             # riwayat
```

Terhubung ke GitHub:

```bash
git remote add origin https://github.com/user/repo.git
git push -u origin main       # kirim ke GitHub
git pull                      # ambil perubahan terbaru
git clone <url>               # salin repo orang
```

Bekerja dengan branch:

```bash
git checkout -b fitur-login   # bikin & pindah ke branch baru
git checkout main             # balik ke main
git merge fitur-login         # gabungkan
```

Kenapa branch? Supaya eksperimen kamu nggak merusak kode yang sudah jalan. Di tim, tiap fitur dikerjakan di branch sendiri lalu digabung lewat **Pull Request** — tempat kode direview sebelum masuk.

### `.gitignore`

```
venv/
__pycache__/
.env
*.log
```

⚠️ Jangan pernah commit file `.env`, password, atau API key. Sekali ter-push ke repo publik, anggap saja sudah bocor.

## Alur kerja harian

```bash
git pull                       # 1. ambil yang terbaru
source venv/bin/activate       # 2. aktifkan env
# ... ngoding ...
pytest                         # 3. pastikan test hijau
git add . && git commit -m "..."   # 4. simpan
git push                       # 5. kirim
```

## Ringkasan

- `pip` memasang library; daftarnya dicatat di `requirements.txt`.
- `venv` memisahkan library tiap proyek supaya tidak bentrok.
- Git menyimpan riwayat perubahan; branch memisahkan pekerjaan.
- `.gitignore` menjaga file rahasia dan sampah tidak ikut ter-commit.

## Kesalahan umum

- Menginstall semua library secara global sampai saling bentrok.
- Lupa mengaktifkan venv, lalu bingung kenapa `ModuleNotFoundError`.
- Commit folder `venv/` atau file `.env` ke repo publik.
