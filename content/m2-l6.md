## Di mana sebuah variabel "hidup"?

Variabel yang dibuat di dalam fungsi hanya ada di dalam fungsi itu. Begitu fungsinya selesai, variabelnya hilang. Itu namanya **scope**.

```python
def f():
    pesan = "halo"      # variabel LOKAL
    print(pesan)

f()               # halo
print(pesan)      # 💥 NameError: name 'pesan' is not defined
```

Ini fitur, bukan keterbatasan: berkat scope, kamu bisa memakai nama `total` di sepuluh fungsi berbeda tanpa saling bertabrakan.

Sebaliknya, variabel di luar fungsi (**global**) bisa dibaca dari dalam:

```python
pajak = 0.1

def total(harga):
    return harga + harga * pajak    # boleh membaca pajak

print(total(1000))    # 1100.0
```

## Membaca boleh, menimpa bikin variabel baru

```python
x = 1

def f():
    x = 2        # ini variabel LOKAL baru, bukan x yang di luar
    print(x)     # 2

f()
print(x)         # 1  <- yang di luar tidak berubah
```

Python memutuskan ini **saat membaca kode**, bukan saat menjalankannya. Begitu ada penugasan ke `x` di mana pun dalam fungsi, `x` dianggap lokal untuk seluruh fungsi itu:

```python
x = 1

def f():
    print(x)     # 💥 UnboundLocalError
    x = 2        # baris ini membuat x jadi lokal, termasuk di baris atas

f()
```

Error ini membingungkan pertama kali, tapi sekarang kamu tahu penyebabnya.

Kalau benar-benar perlu mengubah yang global:

```python
x = 1

def f():
    global x
    x = 2

f()
print(x)    # 2
```

Tapi **hindari `global`**. Fungsi yang diam-diam mengubah keadaan di luar bikin bug yang susah dilacak dan sulit diuji. Lebih baik: terima lewat parameter, kembalikan lewat `return`.

```python
# ❌
def tambah():
    global total
    total += 1

# ✅
def tambah(total):
    return total + 1
```

## Aturan LEGB

Python mencari nama variabel secara berurutan:

| Urutan | Cakupan | Contoh |
|---|---|---|
| **L**ocal | di dalam fungsi sekarang | variabel biasa di dalam `def` |
| **E**nclosing | fungsi pembungkusnya | fungsi di dalam fungsi |
| **G**lobal | level file | variabel di luar semua fungsi |
| **B**uilt-in | bawaan Python | `len`, `print`, `sum` |

```python
x = "global"

def luar():
    x = "enclosing"
    def dalam():
        print(x)      # enclosing — ditemukan lebih dulu
    dalam()

luar()
```

Karena built-in ada di urutan terakhir, menamai variabel `list`, `str`, atau `sum` akan **menutupi** fungsi bawaan:

```python
sum = 10
print(sum([1, 2]))   # 💥 TypeError: 'int' object is not callable
```

### `nonlocal` untuk enclosing

```python
def penghitung():
    n = 0
    def naik():
        nonlocal n      # merujuk n milik penghitung, bukan bikin baru
        n += 1
        return n
    return naik

c = penghitung()
print(c(), c(), c())    # 1 2 3
```

Fungsi dalam yang "mengingat" variabel fungsi luarnya disebut **closure** — konsep ini jadi dasar decorator di Modul 5.

## Lambda: fungsi satu baris tanpa nama

```python
kuadrat = lambda x: x * x
print(kuadrat(4))     # 16
```

Bentuknya `lambda parameter: ekspresi`. Isinya cuma boleh **satu ekspresi**, dan hasilnya otomatis dikembalikan (tidak ada `return`).

Yang tidak bisa dilakukan lambda:

```python
lambda x: x = 5              # ❌ tidak bisa menugaskan
lambda x: if x: ...          # ❌ tidak bisa if statement (ternary boleh)
lambda x: print(x); print(y) # ❌ tidak bisa beberapa baris
```

⚠️ Lambda bukan buat disimpan ke variabel. Kalau begitu, pakai `def` saja — lebih jelas dan punya nama yang muncul di traceback:

```python
kuadrat = lambda x: x * x      # 😐 gaya yang tidak dianjurkan
def kuadrat(x): return x * x   # ✅
```

Kegunaan aslinya: **dikirim sebagai argumen ke fungsi lain**, untuk logika sekali pakai yang tidak layak diberi nama.

## `sorted(key=...)` — tempat lambda bersinar

```python
orang = [
    {"nama": "Ani", "umur": 30},
    {"nama": "Budi", "umur": 20},
]

urut = sorted(orang, key=lambda o: o["umur"])
print(urut[0]["nama"])    # Budi
```

`key` menerima sebuah fungsi yang menentukan "dinilai dari apa" tiap elemen.

```python
kata = ["banana", "kiwi", "apple"]

sorted(kata, key=len)                 # ['kiwi', 'apple', 'banana']
sorted(kata, key=lambda s: s[-1])     # urut berdasarkan huruf terakhir
sorted(orang, key=lambda o: -o["umur"])              # menurun
sorted(orang, key=lambda o: o["umur"], reverse=True) # lebih jelas
sorted(orang, key=lambda o: (o["umur"], o["nama"]))  # dua kriteria
```

Lambda juga sering dipakai bersama `max`, `min`, `filter`, dan `map`:

```python
termuda = min(orang, key=lambda o: o["umur"])
dewasa = list(filter(lambda o: o["umur"] >= 21, orang))
nama = list(map(lambda o: o["nama"], orang))
```

Walau untuk dua contoh terakhir, comprehension biasanya lebih terbaca:

```python
dewasa = [o for o in orang if o["umur"] >= 21]
nama = [o["nama"] for o in orang]
```

## Fungsi sebagai nilai

Di Python, fungsi adalah objek biasa — bisa disimpan, dikirim, dan dikembalikan:

```python
def tambah(a, b): return a + b
def kali(a, b): return a * b

operasi = {"+": tambah, "*": kali}
print(operasi["+"](2, 3))     # 5
print(operasi["*"](2, 3))     # 6
```

Perhatikan bedanya:

```python
f = tambah      # menyimpan FUNGSINYA
f = tambah(1,2) # menyimpan HASILNYA
```

Kemampuan inilah yang membuat `key=`, `filter`, dan decorator mungkin.

## Ringkasan

- Variabel lokal hidup hanya selama fungsinya berjalan; scope mencegah nama bertabrakan.
- Fungsi boleh membaca variabel global, tapi menugaskan padanya membuat variabel lokal baru.
- Urutan pencarian nama: Local → Enclosing → Global → Built-in (LEGB).
- Hindari `global`; terima lewat parameter, kembalikan lewat `return`.
- `lambda x: ...` adalah fungsi singkat, paling berguna sebagai argumen `key=`.

## Kesalahan umum

- Mengira variabel di dalam fungsi bisa dibaca dari luar.
- `UnboundLocalError` karena membaca variabel global yang juga ditugaskan di fungsi itu.
- Menimpa nama bawaan seperti `list`, `sum`, `id`.
- Menyimpan lambda ke variabel padahal `def` lebih tepat.
