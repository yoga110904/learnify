## Dari teks ke angka

Model hanya paham angka. Jadi teks melewati dua tahap:

```
"kucing lucu" → tokenisasi → [8127, 3390] → embedding → [[0.2, -0.5, ...], [...]]
```

## Tokenisasi

Memecah teks jadi potongan yang ada di kosakata model.

```python
kosakata = {"halo": 0, "dunia": 1, "!": 2, "<unk>": 3}

def tokenisasi(teks, kosakata):
    return [kosakata.get(k, kosakata["<unk>"]) for k in teks.lower().split()]

tokenisasi("halo dunia", kosakata)     # [0, 1]
tokenisasi("halo bumi", kosakata)      # [0, 3]  <- tidak dikenal
```

Model asli memakai **subword tokenization** (BPE): kata umum jadi satu token, kata jarang dipecah jadi potongan. Dengan begitu kosakatanya tetap kecil tapi bisa menangani kata apa pun, termasuk salah ketik dan nama asing.

Token khusus yang sering ada: `<pad>` (penyeragam panjang), `<unk>` (tak dikenal), `<eos>` (akhir teks).

## Embedding

Token ID cuma nomor urut — angka 8127 tidak lebih besar maknanya dari 3390. **Embedding** memetakan tiap token ke vektor yang menangkap maknanya.

```python
import numpy as np
embedding = np.array([
    [0.9, 0.1],    # "kucing"
    [0.8, 0.2],    # "anjing"   <- dekat dengan kucing (sama-sama hewan)
    [0.1, 0.9],    # "mobil"    <- jauh
])
```

Vektor ini **dipelajari** dari data. Kata yang sering muncul di konteks serupa berakhir berdekatan di ruang vektor.

Hasilnya, hubungan makna jadi bisa dihitung:

```
vektor("raja") - vektor("pria") + vektor("wanita") ≈ vektor("ratu")
```

Embedding kalimat modern (OpenAI, Cohere, sentence-transformers) memampatkan seluruh kalimat jadi satu vektor 768–1536 dimensi. Prinsipnya sama persis, cuma lebih besar.

## Mencari teks yang mirip

Di sinilah cosine similarity dari Modul 8 terpakai langsung.

```python
import numpy as np

def cosine(a, b):
    na, nb = np.linalg.norm(a), np.linalg.norm(b)
    return 0.0 if na == 0 or nb == 0 else float(a @ b / (na * nb))

dokumen = np.array([
    [0.9, 0.1],    # "cara merawat kucing"
    [0.1, 0.9],    # "harga mobil bekas"
])
kueri = np.array([0.85, 0.15])   # "kucing saya sakit"

skor = [cosine(kueri, d) for d in dokumen]
print(np.argmax(skor))    # 0  ✅
```

Ini fondasi pencarian semantik: **mencari berdasarkan makna, bukan kecocokan kata**. Kueri "hewan peliharaan" bisa menemukan dokumen tentang kucing walaupun kata "hewan peliharaan" tidak pernah muncul di sana.

## Pencarian kata kunci vs semantik

| | Kata kunci (BM25) | Semantik (embedding) |
|---|---|---|
| Cocok untuk | nama, kode produk, istilah persis | makna, parafrase |
| Lemah pada | sinonim, salah ketik | istilah teknis yang sangat spesifik |

Sistem produksi yang bagus biasanya menggabungkan keduanya (*hybrid search*).

## Vector database

Untuk jutaan dokumen, membandingkan satu per satu terlalu lambat. **Vector database** (FAISS, Chroma, Pinecone, pgvector) memakai indeks perkiraan sehingga pencarian tetap cepat.

Alurnya:

```
1. Pecah dokumen jadi potongan (chunk)
2. Ubah tiap potongan jadi embedding
3. Simpan di vector DB
4. Saat ada pertanyaan → embed → cari yang paling mirip
```

Langkah 4 itulah yang akan kita pakai di lesson RAG.

## Ringkasan

- Teks → token → embedding sebelum bisa diproses model.
- Subword tokenization membuat kosakata kecil tapi tetap bisa menangani kata apa pun.
- Embedding memetakan makna ke vektor; kata bermakna serupa berdekatan.
- Cosine similarity mencari teks termirip — dasar pencarian semantik dan RAG.

## Kesalahan umum

- Mengira token ID sudah punya makna (padahal cuma nomor).
- Membandingkan embedding dari model yang berbeda — ruang vektornya tidak sama.
- Memakai pencarian semantik untuk kode produk, yang justru butuh kecocokan persis.
