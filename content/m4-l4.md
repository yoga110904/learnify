## Satu perintah, banyak perilaku

**Polymorphism** artinya "banyak bentuk": objek yang berbeda merespons perintah yang sama dengan caranya masing-masing.

Tombol "print" di komputer: printer inkjet, laser, dan PDF menanggapi perintah yang sama dengan mekanisme berbeda. Kamu nggak perlu tahu caranya.

```python
class Kucing:
    def bersuara(self):
        return "Meong"

class Anjing:
    def bersuara(self):
        return "Guk"

for hewan in [Kucing(), Anjing()]:
    print(hewan.bersuara())    # Meong / Guk
```

Loop-nya tidak peduli jenis objeknya. Asal punya method `bersuara()`, semuanya diperlakukan sama.

## Duck typing

Filosofi Python: *"Kalau jalannya kayak bebek dan bunyinya kayak bebek, ya anggap saja bebek."*

Python **tidak** memeriksa tipe objek, dia cuma memanggil method-nya. Objek apa pun yang punya method dengan nama yang cocok akan jalan:

```python
class Robot:
    def bersuara(self):
        return "Beep"

hewan = [Kucing(), Anjing(), Robot()]   # Robot bukan hewan, tapi tetap jalan
```

Inilah yang bikin **mocking** di testing gampang: kamu cukup bikin objek palsu yang punya method yang sama dengan aslinya.

## Abstract Base Class

Kadang kita mau memaksa: "semua turunan **wajib** punya method `luas()`". Kalau lupa, harus error sejak awal, bukan diam-diam salah.

```python
from abc import ABC, abstractmethod

class Bentuk(ABC):
    @abstractmethod
    def luas(self):
        ...

class Persegi(Bentuk):
    def __init__(self, s):
        self.s = s
    def luas(self):
        return self.s ** 2

class Lingkaran(Bentuk):
    def __init__(self, r):
        self.r = r
    def luas(self):
        return 3.14159 * self.r ** 2
```

Aturannya:

```python
Bentuk()          # 💥 TypeError: Can't instantiate abstract class
Persegi(2).luas() # 4  ✅
```

Dan kalau ada turunan yang lupa mengimplementasikan `luas()`, dia juga langsung ditolak saat dibuat. Error cepat jauh lebih baik daripada bug diam-diam.

## Memakai polymorphism

```python
def total_luas(daftar):
    return sum(b.luas() for b in daftar)

print(round(total_luas([Persegi(2), Lingkaran(1)]), 2))   # 7.14
```

`total_luas` tidak perlu tahu ada bentuk apa saja. Besok kamu tambah `Segitiga`, fungsi ini tidak perlu diubah sama sekali — itu tanda desain yang bagus.

Bandingkan dengan versi tanpa polymorphism:

```python
def total_luas(daftar):           # ❌ harus diedit tiap ada bentuk baru
    total = 0
    for b in daftar:
        if isinstance(b, Persegi):
            total += b.s ** 2
        elif isinstance(b, Lingkaran):
            total += 3.14159 * b.r ** 2
    return total
```

## Ringkasan

- Polymorphism: objek berbeda merespons method yang sama dengan caranya sendiri.
- Duck typing: Python peduli method yang dimiliki, bukan tipe class-nya.
- `ABC` + `@abstractmethod` memaksa turunan mengimplementasikan method tertentu.
- Kode yang memanggil method umum tidak perlu diubah saat muncul tipe baru.

## Kesalahan umum

- Menumpuk `if isinstance(...)` padahal cukup polymorphism.
- Lupa `@abstractmethod` sehingga aturan tidak dipaksakan.
- Mencoba membuat objek langsung dari abstract class.
