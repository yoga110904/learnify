## Kenapa harus nulis test?

Kamu memperbaiki satu baris di fitur diskon. Apakah fitur checkout masih jalan? Fitur kupon? Fitur laporan? Tanpa test, jawabannya cuma "kayaknya sih iya".

Test adalah **jaring pengaman**: sekumpulan kode yang memeriksa kode lain secara otomatis, dalam hitungan detik.

## pytest: sederhana sampai membosankan

```python
# file: test_diskon.py
def diskon(harga, persen):
    return harga - harga * persen / 100

def test_diskon_10_persen():
    assert diskon(100, 10) == 90
```

Jalankan:

```bash
pip install pytest
pytest
```

```
test_diskon.py .                    [100%]
========== 1 passed in 0.01s ==========
```

Cuma butuh `assert` biasa — tidak ada `assertEquals` atau boilerplate class seperti di framework lain.

## Aturan penamaan (ini yang bikin otomatis ketemu)

pytest menemukan test lewat konvensi nama:

- File: `test_*.py` atau `*_test.py`
- Fungsi: diawali `test_`
- Class (opsional): diawali `Test`, dan tidak punya `__init__`

Kalau test-mu tidak pernah jalan, 9 dari 10 kasus penyebabnya nama file atau fungsi yang salah.

## Pola AAA: Arrange – Act – Assert

Struktur baku yang bikin test gampang dibaca:

```python
def test_total_belanja():
    # Arrange — siapkan data
    keranjang = [10, 20, 30]

    # Act — jalankan yang mau diuji
    hasil = total(keranjang)

    # Assert — periksa hasilnya
    assert hasil == 60
```

Satu test sebaiknya memeriksa **satu perilaku**. Namanya jelaskan perilakunya:

```python
def test_1():                              # ❌ tidak berarti
def test_diskon_nol_persen_tidak_mengubah_harga():   # ✅
```

## Membaca laporan gagal

```python
def test_diskon():
    assert diskon(100, 10) == 80
```

```
E       assert 90.0 == 80
E        +  where 90.0 = diskon(100, 10)

test_diskon.py:5: AssertionError
========== 1 failed in 0.02s ==========
```

pytest otomatis menunjukkan nilai sebenarnya vs yang diharapkan. Bacanya dari bawah: nama file dan baris, lalu detail perbandingan.

## Menguji bahwa error memang terjadi

```python
import pytest

def test_tarik_melebihi_saldo():
    with pytest.raises(ValueError):
        tarik(100, 500)
```

Test ini gagal kalau `tarik` **tidak** melempar `ValueError` — yaitu persis validasi yang kita bangun di Modul 4.

## Perintah yang sering dipakai

```bash
pytest                       # semua test
pytest test_login.py         # satu file
pytest -k "diskon"           # hanya yang namanya mengandung "diskon"
pytest -v                    # tampilkan nama tiap test
pytest -q                    # ringkas
pytest -x                    # berhenti di kegagalan pertama
pytest --tb=short            # traceback lebih pendek
```

## Test yang baik itu seperti apa?

Ingat singkatan **FIRST**:

- **F**ast — cepat, supaya sering dijalankan
- **I**ndependent — tidak bergantung urutan test lain
- **R**epeatable — hasilnya sama setiap kali (hati-hati dengan tanggal & random)
- **S**elf-validating — lulus/gagal jelas, tanpa perlu membaca output manual
- **T**imely — ditulis berdekatan dengan kodenya

Dan jangan cuma menguji "jalan normal". Kasus batas justru yang paling sering bikin bug: nilai 0, list kosong, angka negatif, string kosong, nilai tepat di batas.

## Ringkasan

- Test otomatis memberi keyakinan saat mengubah kode.
- pytest memakai `assert` biasa dan menemukan test lewat konvensi nama.
- Susun test dengan pola Arrange–Act–Assert, satu perilaku per test.
- `pytest.raises` menguji bahwa exception memang dilempar.

## Kesalahan umum

- Nama file/fungsi tidak diawali `test_` sehingga tidak pernah dijalankan.
- Satu test memeriksa sepuluh hal sekaligus — waktu gagal, sulit tahu penyebabnya.
- Hanya menguji kasus normal, tidak menguji kasus batas.
