## Fungsi yang memanggil dirinya sendiri

Pernah lihat boneka matryoshka? Buka satu, di dalamnya ada yang lebih kecil, buka lagi, lebih kecil lagi — sampai ketemu yang paling kecil dan nggak bisa dibuka. Itulah **rekursi**.

```python
def hitung_mundur(n):
    if n == 0:            # base case — boneka terkecil
        print("Selesai!")
        return
    print(n)
    hitung_mundur(n - 1)  # recursive case — buka boneka berikutnya

hitung_mundur(3)
```

```
3
2
1
Selesai!
```

## Dua bagian wajib

Setiap fungsi rekursif harus punya:

1. **Base case** — kondisi berhenti. Tanpa ini, rekursinya nggak pernah selesai.
2. **Recursive case** — memanggil diri sendiri dengan input yang **makin mendekati base case**.

```python
def faktorial(n):
    if n <= 1:                   # base case
        return 1
    return n * faktorial(n - 1)  # recursive case

print(faktorial(5))    # 120
```

Kalau dibongkar:

```
faktorial(5)
= 5 * faktorial(4)
= 5 * 4 * faktorial(3)
= 5 * 4 * 3 * faktorial(2)
= 5 * 4 * 3 * 2 * faktorial(1)
= 5 * 4 * 3 * 2 * 1
= 120
```

Perhatikan: pemanggilan **menumpuk dulu sampai ke base case**, baru hasilnya dihitung balik ke atas. Ini penting dipahami — nilai sesungguhnya baru muncul saat "perjalanan pulang".

## Melihat prosesnya

Tambahkan `print` untuk melihat tumpukannya:

```python
def faktorial(n, level=0):
    print("  " * level + f"masuk faktorial({n})")
    if n <= 1:
        print("  " * level + "base case!")
        return 1
    hasil = n * faktorial(n - 1, level + 1)
    print("  " * level + f"faktorial({n}) = {hasil}")
    return hasil

faktorial(3)
```

```
masuk faktorial(3)
  masuk faktorial(2)
    masuk faktorial(1)
    base case!
  faktorial(2) = 2
faktorial(3) = 6
```

Teknik ini sangat membantu saat rekursimu tidak berperilaku seperti yang kamu kira.

## Fibonacci & masalah performanya

```python
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

print([fib(i) for i in range(8)])   # [0, 1, 1, 2, 3, 5, 8, 13]
```

Versi ini benar tapi **sangat lambat**: `fib(30)` memanggil dirinya lebih dari 2,7 juta kali karena menghitung nilai yang sama berulang-ulang.

Perbaikannya dengan cache:

```python
from functools import lru_cache

@lru_cache
def fib(n):
    return n if n < 2 else fib(n - 1) + fib(n - 2)

print(fib(100))    # instan
```

Satu baris `@lru_cache` mengubah waktu eksekusi dari "tidak selesai-selesai" jadi seketika, karena tiap nilai cuma dihitung sekali. Decorator `@` dibahas di Modul 5.

Alternatif tanpa rekursi, pakai loop:

```python
def fib(n):
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a
```

Versi ini paling cepat dan paling hemat memori. Pelajarannya: **rekursi bukan selalu jawaban terbaik**.

## Batas rekursi

Tiap pemanggilan menumpuk memori di "call stack". Python membatasi sekitar 1000 tingkat:

```python
import sys
print(sys.getrecursionlimit())   # 1000

def f(n):
    return f(n + 1)

f(1)    # 💥 RecursionError: maximum recursion depth exceeded
```

Lupa base case menghasilkan error yang sama. Menaikkan batasnya bisa, tapi biasanya tanda bahwa solusinya sebaiknya pakai loop.

## Kapan rekursi layak dipakai?

Bagus untuk data yang bentuknya **bersarang** dan kedalamannya tidak diketahui:

| Cocok | Lebih baik pakai loop |
|---|---|
| Struktur folder | Menjumlah list |
| JSON bertingkat | Mencetak 1–100 |
| Pohon kategori/komentar | Mencari di list datar |
| Algoritma divide-and-conquer | Iterasi sederhana |

### Meratakan data bersarang

```python
def flatten(data):
    hasil = []
    for item in data:
        if isinstance(item, list):
            hasil.extend(flatten(item))   # item ini list -> gali lagi
        else:
            hasil.append(item)
    return hasil

print(flatten([1, [2, [3, [4]]]]))   # [1, 2, 3, 4]
```

Coba tulis ini dengan loop biasa — kamu akan butuh tumpukan manual, dan hasilnya jauh lebih panjang. Di sinilah rekursi menang.

### Menjelajah struktur bersarang

```python
def cari_kunci(data, target):
    """Cari nilai sebuah kunci di dict bersarang sedalam apa pun."""
    if isinstance(data, dict):
        for k, v in data.items():
            if k == target:
                return v
            hasil = cari_kunci(v, target)
            if hasil is not None:
                return hasil
    elif isinstance(data, list):
        for item in data:
            hasil = cari_kunci(item, target)
            if hasil is not None:
                return hasil
    return None

data = {"a": {"b": {"c": 42}}}
print(cari_kunci(data, "c"))    # 42
```

## Menulis fungsi rekursif: resepnya

1. **Tentukan base case.** Kasus paling sederhana yang jawabannya langsung diketahui.
2. **Tentukan recursive case.** Bagaimana masalah besar dikecilkan jadi versi yang sama tapi lebih kecil?
3. **Pastikan mengecil.** Tiap pemanggilan harus lebih dekat ke base case.
4. **Percaya.** Anggap pemanggilan rekursifnya sudah benar — jangan coba melacak seluruh tumpukannya di kepala.

Poin terakhir itu yang paling sulit tapi paling membebaskan. Kalau `faktorial(n-1)` sudah benar, maka `n * faktorial(n-1)` pasti benar juga.

```python
def kedalaman(data):
    if not isinstance(data, list):
        return 0
    if not data:
        return 1
    return 1 + max(kedalaman(item) for item in data)

print(kedalaman([1, [2, [3]]]))    # 3
print(kedalaman([]))               # 1
print(kedalaman(5))                # 0
```

## Ringkasan

- Rekursi = fungsi memanggil dirinya sendiri; wajib punya base case dan recursive case.
- Pemanggilan menumpuk sampai base case, lalu hasilnya dihitung balik ke atas.
- Rekursi polos bisa sangat lambat kalau menghitung ulang — `@lru_cache` menyelesaikannya.
- Cocok untuk data bersarang; untuk kasus sederhana `for` lebih cepat dan jelas.
- Rekursi terlalu dalam menghasilkan `RecursionError` (batas ±1000).

## Kesalahan umum

- Lupa base case → `RecursionError`.
- Base case ada, tapi argumennya tidak pernah berubah mendekatinya.
- Memakai rekursi untuk kasus yang jelas lebih cocok pakai `for`.
- Mencoba melacak seluruh tumpukan pemanggilan di kepala alih-alih mempercayai base case.
