## Masalah: urutan langkah yang gampang salah

Alur ML biasanya begini:

```
data mentah → isi nilai kosong → samakan skala → latih model
```

Kalau dikerjakan manual, kamu harus mengulang langkah yang **persis sama** untuk data uji dan data produksi. Sekali lupa satu langkah, hasilnya diam-diam salah.

**Pipeline** membungkus semuanya jadi satu objek.

## Scaler

```python
from sklearn.preprocessing import StandardScaler, MinMaxScaler

scaler = StandardScaler()          # mean 0, std 1
X_train_s = scaler.fit_transform(X_train)
X_test_s  = scaler.transform(X_test)     # transform SAJA
```

Ingat aturannya: `fit_transform` pada data latih, `transform` pada data uji. Kalau `fit` juga dijalankan di data uji, terjadi data leakage.

## Encoder

```python
from sklearn.preprocessing import OneHotEncoder, OrdinalEncoder

OneHotEncoder(handle_unknown='ignore')    # kategori tanpa urutan
OrdinalEncoder()                          # kategori berurutan
```

`handle_unknown='ignore'` penting: di produksi pasti muncul kategori yang tidak ada saat pelatihan, dan tanpa itu programmu akan error.

## Imputer

```python
from sklearn.impute import SimpleImputer

SimpleImputer(strategy='median')                    # untuk angka
SimpleImputer(strategy='most_frequent')             # untuk kategori
```

## Pipeline

```python
from sklearn.pipeline import Pipeline
from sklearn.impute import SimpleImputer
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

pipe = Pipeline([
    ('imputer', SimpleImputer(strategy='median')),
    ('scaler', StandardScaler()),
    ('model', LogisticRegression())
])

pipe.fit(X_train, y_train)
pipe.score(X_test, y_test)
pipe.predict(X_baru)
```

Sekarang `pipe` berperilaku persis seperti satu model biasa. Semua langkah preprocessing ikut tersimpan dan otomatis diterapkan ulang — **tidak mungkin lupa satu langkah**, dan tidak mungkin bocor.

## ColumnTransformer

Kolom angka dan kolom kategori butuh perlakuan berbeda:

```python
from sklearn.compose import ColumnTransformer

pre = ColumnTransformer([
    ('angka', StandardScaler(), ['umur', 'gaji']),
    ('kategori', OneHotEncoder(handle_unknown='ignore'), ['kota'])
])

pipe = Pipeline([('pre', pre), ('model', LogisticRegression())])
```

Inilah bentuk standar pipeline untuk data tabel di dunia nyata.

## Mencari hyperparameter terbaik

```python
from sklearn.model_selection import GridSearchCV

grid = {
    'model__C': [0.1, 1, 10],
    'model__max_iter': [200, 500]
}

cari = GridSearchCV(pipe, grid, cv=5, scoring='f1_macro')
cari.fit(X_train, y_train)

print(cari.best_params_)
print(cari.best_score_)
model_terbaik = cari.best_estimator_
```

Perhatikan penamaannya: `model__C` artinya *parameter `C` milik langkah bernama `model`* — dua garis bawah sebagai pemisah.

Kalau kombinasinya terlalu banyak, pakai `RandomizedSearchCV` yang mencoba sebagian secara acak — biasanya menemukan hasil hampir sebaik GridSearch dengan waktu jauh lebih singkat.

## Menyimpan model

```python
import joblib

joblib.dump(pipe, 'model.pkl')
pipe = joblib.load('model.pkl')
pipe.predict(X_baru)
```

Yang tersimpan adalah seluruh pipeline, lengkap dengan scaler dan encoder-nya. Inilah yang kamu deploy.

## Ringkasan

- Pipeline membungkus preprocessing + model jadi satu objek yang aman dari kebocoran.
- `fit_transform` di data latih, `transform` saja di data uji.
- `ColumnTransformer` memberi perlakuan berbeda untuk kolom angka dan kategori.
- `GridSearchCV` mencari hyperparameter terbaik lewat cross-validation.

## Kesalahan umum

- Menjalankan scaler di seluruh data sebelum split.
- Menyimpan model saja tanpa scaler/encoder-nya.
- Lupa `handle_unknown='ignore'` sehingga error saat ketemu kategori baru.
