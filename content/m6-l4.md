## API testing: lebih cepat dan lebih stabil dari UI test

Test UI membuka browser, menunggu render, dan gampang flaky. API test memanggil endpoint langsung: milidetik, tanpa browser, dan biasanya menangkap bug lebih awal. Di piramida testing, API test adalah lapisan tengah yang jumlahnya harus banyak.

## Kilas balik HTTP

| Method | Arti | Idempotent? |
|---|---|---|
| `GET` | ambil data | ya |
| `POST` | buat data baru | tidak |
| `PUT` | ganti seluruh data | ya |
| `PATCH` | ubah sebagian | ya |
| `DELETE` | hapus | ya |

Status code yang wajib hafal:

| Kode | Arti |
|---|---|
| 200 | OK |
| 201 | Created — **resource berhasil dibuat** |
| 204 | No Content — sukses, tanpa body |
| 400 | Bad Request — input salah |
| 401 | Unauthorized — belum login |
| 403 | Forbidden — login tapi tidak berhak |
| 404 | Not Found |
| 422 | Data tidak lolos validasi |
| 500 | Server error |

Bedakan 401 dan 403: 401 = "kamu siapa?", 403 = "aku tahu kamu siapa, tapi tidak boleh".

## `requests`

```python
import requests

r = requests.get("https://api.example.com/users/1")
print(r.status_code)     # 200
print(r.json())          # dict hasil parsing body JSON
print(r.headers["Content-Type"])
print(r.elapsed.total_seconds())
```

```python
r = requests.post(
    "https://api.example.com/users",
    json={"nama": "Salsa"},                        # otomatis jadi JSON
    headers={"Authorization": "Bearer TOKEN"},
    timeout=10,                                    # selalu pasang timeout
)
assert r.status_code == 201
```

`json=` mengirim body JSON, `data=` mengirim form, `params=` menempel query string.

## Apa saja yang harus diperiksa?

Satu test API yang baik memeriksa lebih dari sekadar status code:

```python
def test_get_user():
    r = requests.get(f"{BASE}/users/1", timeout=10)

    assert r.status_code == 200                       # 1. status
    body = r.json()
    assert {"id", "nama", "email"} <= body.keys()     # 2. field wajib ada
    assert isinstance(body["id"], int)                # 3. tipe data
    assert "@" in body["email"]                       # 4. isi masuk akal
    assert r.elapsed.total_seconds() < 2              # 5. performa
```

Dan jangan lupa jalur negatif — ini yang paling sering terlewat:

```python
def test_user_tidak_ada():
    assert requests.get(f"{BASE}/users/999999").status_code == 404

def test_tanpa_token():
    assert requests.post(f"{BASE}/users", json={}).status_code == 401
```

## Schema validation

Memeriksa field satu per satu jadi melelahkan untuk response besar. Pakai `jsonschema`:

```python
from jsonschema import validate

SCHEMA = {
    "type": "object",
    "required": ["id", "nama", "email"],
    "properties": {
        "id": {"type": "integer"},
        "nama": {"type": "string"},
        "email": {"type": "string", "format": "email"},
    },
}

validate(instance=r.json(), schema=SCHEMA)   # melempar error kalau tidak cocok
```

Sekali definisikan schema, pakai di banyak test.

## Validasi tanpa jaringan

Logika pemeriksaan sebaiknya dipisah jadi fungsi murni — jadi bisa diuji tanpa server sama sekali (dan itulah latihan lesson ini):

```python
WAJIB = ("id", "nama", "email")

def validasi_response(resp):
    if resp.get("status") != 200:
        return False
    body = resp.get("body") or {}
    return all(k in body for k in WAJIB)
```

## Ringkasan

- API test lebih cepat dan lebih stabil daripada UI test.
- 201 berarti resource berhasil dibuat; 401 ≠ 403.
- Periksa status, field wajib, tipe data, isi, dan waktu respons.
- Schema validation memangkas assert yang berulang.

## Kesalahan umum

- Hanya memeriksa status code, isi response tidak divalidasi.
- Tidak menguji jalur negatif (404, 401, input tidak valid).
- Memanggil `requests` tanpa `timeout` sehingga test bisa menggantung.
