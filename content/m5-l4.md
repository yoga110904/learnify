## Petunjuk tipe untuk manusia dan tool

Python tidak mewajibkan tipe. Tapi begitu proyekmu dipakai bertiga, pertanyaan "ini parameternya harus diisi apa?" muncul terus.

```python
def hitung(data):        # data itu apa? list? dict? string?
    ...
```

**Type hints** menjawabnya di tempat:

```python
def hitung(data: list[int]) -> float:
    return sum(data) / len(data)
```

Penting: ini **tidak** memaksa apa pun saat program jalan.

```python
def sapa(nama: str) -> str:
    return "halo " + nama

sapa(123)    # tetap jalan sampai baris + gagal — TypeError, bukan karena hint
```

Hint dibaca oleh editor (autocomplete + peringatan) dan oleh type checker seperti **mypy**. Pythonnya sendiri cuma menyimpannya sebagai catatan.

## Sintaks dasar

```python
umur: int = 20
tinggi: float = 165.5
nama: str = "Salsa"
aktif: bool = True

def bagi(a: int, b: int) -> float:
    return a / b

def cetak(pesan: str) -> None:     # None = tidak mengembalikan apa-apa
    print(pesan)
```

## Koleksi

Sejak Python 3.9 pakai tipe bawaan langsung:

```python
nilai: list[int] = [80, 90]
umur: dict[str, int] = {"budi": 20}
titik: tuple[int, int] = (1, 2)
unik: set[str] = {"a"}
data: list[dict[str, int]] = [{"a": 1}]
```

## `Optional` dan `Union`

Nilai yang boleh `None`:

```python
from typing import Optional

def cari_user(users: dict[int, str], id: int) -> Optional[str]:
    return users.get(id)        # bisa str, bisa None
```

`Optional[str]` sama artinya dengan `str | None`. Sejak Python 3.10 gaya pipa lebih disukai:

```python
def cari_user(users: dict[int, str], id: int) -> str | None:
    return users.get(id)

def proses(x: int | float) -> str: ...
```

## Alias dan struktur yang jelas

```python
Skor = dict[str, int]

def rata(data: Skor) -> float: ...
```

Untuk dict dengan bentuk tetap, `TypedDict` atau `dataclass` jauh lebih jelas:

```python
from dataclasses import dataclass

@dataclass
class User:
    id: int
    nama: str
```

## Mengecek dengan mypy

```bash
pip install mypy
mypy app.py
```

```python
def sapa(nama: str) -> str:
    return nama

sapa(123)
```

```
app.py:4: error: Argument 1 to "sapa" has incompatible type "int"; expected "str"
```

Bug ketahuan sebelum program dijalankan — inilah nilai sesungguhnya dari type hints.

## Membaca annotation dari kode

```python
def f(a: int, b: str) -> bool: ...
print(f.__annotations__)
# {'a': <class 'int'>, 'b': <class 'str'>, 'return': <class 'bool'>}
```

## Ringkasan

- Type hints adalah dokumentasi yang bisa diperiksa mesin, bukan aturan runtime.
- `list[int]`, `dict[str, int]` untuk koleksi.
- `Optional[X]` / `X | None` untuk nilai yang boleh kosong.
- `mypy` menemukan ketidakcocokan tipe sebelum program dijalankan.

## Kesalahan umum

- Mengira Python akan menolak argumen yang tipenya salah.
- Menulis hint sangat rumit sampai lebih sulit dibaca daripada kodenya.
- Memberi hint di sebagian fungsi saja sehingga mypy tidak banyak membantu.
