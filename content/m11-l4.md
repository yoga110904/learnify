## Masalah: LLM tidak tahu datamu

Model dilatih sampai tanggal tertentu dan tidak pernah melihat dokumen internal perusahaanmu. Tanya soal kebijakan cutimu, dia akan mengarang.

Ada dua jalan keluar:

| Cara | Biaya | Cocok untuk |
|---|---|---|
| **Fine-tuning** | mahal, perlu data banyak | mengubah gaya & perilaku |
| **RAG** | murah, langsung bisa | menambahkan pengetahuan faktual |

Untuk "model harus tahu isi dokumen kami", **RAG hampir selalu jawabannya.**

## Cara kerja RAG

*Retrieval-Augmented Generation* — cari dulu, baru jawab.

```
1. Pertanyaan pengguna masuk
2. Cari potongan dokumen paling relevan   ← retrieval
3. Tempelkan potongan itu ke prompt        ← augmentation
4. Minta model menjawab HANYA dari situ    ← generation
```

Analoginya: ujian *open book*. Model tidak perlu hafal — dia cukup pintar membaca halaman yang tepat.

## Tahap 1: Chunking

Dokumen dipecah jadi potongan kecil. Ukurannya menentukan kualitas:

- Terlalu besar → ada informasi tidak relevan ikut masuk, konteks jadi berisik
- Terlalu kecil → konteksnya terputus dan maknanya hilang

Patokan umum: **300–800 karakter**, dengan **tumpang tindih 10–20%** supaya kalimat yang terpotong di batas tidak kehilangan makna.

```python
def potong(teks, ukuran=500, tumpang=100):
    potongan = []
    i = 0
    while i < len(teks):
        potongan.append(teks[i:i + ukuran])
        i += ukuran - tumpang
    return potongan
```

Untuk dokumen terstruktur, memotong per paragraf atau per judul biasanya lebih baik daripada memotong per jumlah karakter.

## Tahap 2: Indexing

```python
# semu — di produksi memakai model embedding sungguhan
embedding = [embed(p) for p in potongan]
```

Simpan di vector database beserta metadatanya (nama file, nomor halaman) supaya jawabannya bisa mencantumkan sumber.

## Tahap 3: Retrieval

```python
import numpy as np

def cari(kueri_vec, index, k=3):
    skor = []
    for i, v in enumerate(index):
        na, nb = np.linalg.norm(kueri_vec), np.linalg.norm(v)
        s = 0.0 if na == 0 or nb == 0 else float(kueri_vec @ v / (na * nb))
        skor.append((s, i))
    skor.sort(reverse=True)
    return [i for _, i in skor[:k]]
```

`k` biasanya 3–5. Terlalu banyak potongan justru membuat model bingung dan biayanya membengkak.

## Tahap 4: Generation

```python
def bangun_prompt(pertanyaan, potongan):
    konteks = "\n\n".join(f"[{i+1}] {p}" for i, p in enumerate(potongan))
    return f"""Jawab pertanyaan HANYA berdasarkan konteks di bawah.
Kalau jawabannya tidak ada di konteks, katakan "Tidak ada informasinya di dokumen."
Sebutkan nomor sumber yang kamu pakai.

Konteks:
{konteks}

Pertanyaan: {pertanyaan}
Jawaban:"""
```

Dua kalimat instruksi itu yang paling penting: **"hanya berdasarkan konteks"** dan **"katakan kalau tidak ada"**. Tanpa keduanya, model akan kembali mengarang.

## Kenapa RAG gagal?

Hampir selalu di tahap **retrieval**, bukan generation:

| Gejala | Penyebab |
|---|---|
| Jawaban ngawur | potongan yang diambil tidak relevan |
| "Tidak ada informasinya" padahal ada | chunking memotong konteks penting |
| Jawaban tidak lengkap | `k` terlalu kecil |
| Lambat & mahal | `k` terlalu besar |

Saat men-debug, **cetak dulu potongan yang diambil**. Kalau manusia saja tidak bisa menjawab dari potongan itu, model juga tidak akan bisa.

## Peningkatan lanjutan

- **Hybrid search** — gabungkan pencarian kata kunci dan semantik
- **Reranking** — ambil 20 kandidat, lalu urutkan ulang dengan model khusus, ambil 3 teratas
- **Query rewriting** — ubah pertanyaan jadi bentuk yang lebih mudah dicari
- **Citation** — wajibkan model menyebut nomor sumber agar bisa diperiksa

## Ringkasan

- RAG menambahkan pengetahuan tanpa melatih ulang model.
- Alurnya: chunk → embed → simpan → cari → tempel ke prompt → jawab.
- Chunk 300–800 karakter dengan tumpang tindih; `k` biasanya 3–5.
- Perintahkan model menjawab hanya dari konteks dan mengaku kalau tidak tahu.

## Kesalahan umum

- Menyalahkan model padahal yang salah potongan yang diambil.
- Chunk terlalu besar sehingga konteksnya berisik.
- Lupa menyuruh model bilang "tidak tahu" sehingga dia mengarang.
