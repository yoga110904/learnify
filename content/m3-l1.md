## Program yang tidak langsung mati

Program yang bagus bukan yang nggak pernah error, tapi yang **siap** waktu error datang. User bakal ngetik huruf di kolom umur, file bakal hilang, internet bakal putus.

```python
umur = int(input("Umur: "))    # user ketik "abc" -> program mati
```

## Kenalan dulu dengan error yang umum

| Error | Kapan muncul | Contoh |
|---|---|---|
| `ValueError` | tipe benar, nilainya salah | `int("abc")` |
| `TypeError` | tipe datanya salah | `"5" + 3` |
| `KeyError` | kunci dict nggak ada | `d["hilang"]` |
| `IndexError` | index list kelewat | `[1,2][5]` |
| `ZeroDivisionError` | bagi nol | `1 / 0` |
| `FileNotFoundError` | file nggak ketemu | `open("x.txt")` |
| `AttributeError` | method/atribut nggak ada | `"abc".push()` |

## `try` / `except`

```python
try:
    umur = int(input("Umur: "))
    print("Tahun depan:", umur + 1)
except ValueError:
    print("Masukkan angka, ya.")
```

Alurnya: Python menjalankan blok `try`. Begitu ada error yang cocok dengan `except`, sisa blok `try` dilewati dan blok `except` dijalankan. Program **tetap hidup**.

### Tangkap error spesifik, jangan asal

```python
# ❌ menelan semua error, termasuk typo kamu sendiri
try:
    proses()
except:
    pass

# ✅ jelas apa yang diantisipasi
try:
    proses()
except (ValueError, TypeError) as e:
    print("Data tidak valid:", e)
```

`as e` menyimpan objek error-nya supaya pesannya bisa dibaca atau dicatat ke log.

## `else` dan `finally`

```python
try:
    hasil = 10 / 2
except ZeroDivisionError:
    print("tidak bisa dibagi nol")
else:
    print("sukses:", hasil)    # jalan hanya kalau TIDAK ada error
finally:
    print("selalu jalan")      # jalan apa pun yang terjadi
```

`finally` biasanya dipakai buat beres-beres: menutup file, menutup koneksi database, melepas model dari memori.

## `raise` — melempar error sendiri

Kadang kita yang harus bilang "ini nggak boleh":

```python
def tarik(saldo, jumlah):
    if jumlah > saldo:
        raise ValueError("Saldo tidak cukup")
    return saldo - jumlah

try:
    tarik(100, 500)
except ValueError as e:
    print("Gagal:", e)     # Gagal: Saldo tidak cukup
```

Melempar error lebih jujur daripada diam-diam mengembalikan `None` — pemanggilnya jadi tahu ada yang salah.

## Exception buatan sendiri

```python
class SaldoKurangError(Exception):
    pass

def tarik(saldo, jumlah):
    if jumlah > saldo:
        raise SaldoKurangError(f"Kurang {jumlah - saldo}")
```

Berguna supaya pemanggil bisa menangani jenis kegagalan tertentu secara khusus.

## Ringkasan

- `try`/`except` mencegah program berhenti mendadak.
- Tangkap exception yang spesifik, jangan `except:` polos.
- `else` jalan kalau tidak ada error; `finally` selalu jalan.
- `raise` dipakai untuk melaporkan kondisi yang tidak valid.

## Kesalahan umum

- `except:` kosong yang menyembunyikan bug asli.
- Membungkus terlalu banyak baris dalam satu `try` sehingga sulit tahu mana yang gagal.
- Menangkap error tapi tidak melakukan apa-apa (`pass`) tanpa alasan.
